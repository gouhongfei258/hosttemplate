# 设备

PLC 与字节流、HTTP、Open Protocol 的封装。工站步骤只依赖 `HostTemplate.Core.Abstractions` 里的接口；具体对象由 `Program` 或业务代码创建。配置加载见 [配置](配置.md)。

## 1. 结果和接口

通信失败返回 `DeviceResult` 或 `DeviceResult<T>`，不抛异常。`Success` 为 false 时 `Error` 是原因，泛型的 `Value` 为 `default`。主循环因此不必为单次读写包 try/catch。取消令牌抛出的 `OperationCanceledException` 会继续向外抛。

`IPlcClient` 是引擎使用的 PLC 接口：

| 方法 | 作用 |
|---|---|
| `OpenAsync` / `CloseAsync` | 连接和断开。同时实现 `IDisposable` 与 `IAsyncDisposable` |
| `IsConnected` / `Address` | 连接状态和地址 |
| `ReadBoolAsync` / `ReadBoolArrayAsync` | 位 |
| `ReadWordAsync` / `ReadWordArrayAsync` | Word |
| `ReadInt32Async` / `ReadRealAsync` / `ReadStringAsync` | 双字、浮点、字符串 |
| `WriteBoolAsync` / `WriteWordAsync` / `WriteInt32Async` / `WriteRealAsync` / `WriteStringAsync` | 对应的写 |

`IApiClient` 是 MES 客户端：`IsAvailable`、`PostAsync(endpointKey, payload, cancellationToken)`、`PingAsync`。实现是 `HostTemplate.Devices.Api.HttpApiClient`，按 `api.xml` 工作。它和下面的 `HslHttpClient` 不是同一个类型。

`IDevice` 是字节流：`OpenAsync`、`CloseAsync`、`SendAsync`、`ReceiveAsync(maxLength)`。`ReceiveAsync` 只取当前已经到达的数据，最多 `maxLength` 字节，不等待凑满。凑满定长帧用各实现上的 `ReceiveExactAsync`。

## 2. HSL 设备基类

`HslDeviceBase` 实现 `IPlcClient`。子类负责创建具体协议对象，并设置 `ConnectAction`（调用 HSL 的 `ConnectServerAsync`）和 `CloseAction`（调用 `ConnectCloseAsync`）。读写都走 HSL 的 `*Async` 方法。

行为：

- 同一客户端上的打开、关闭和读写用 `SemaphoreSlim` 串行。取消令牌用于取消排队，并在真正调用 HSL 之前检查一次。HSL 12.8.3 的 Async 方法不接收 `CancellationToken`，已经进入 HSL 的调用不会被这个令牌打断。
- 未连接时读写直接返回「设备未连接」，不在读写里隐式重连。重连由 `StationEngine` 按 `ReconnectDelayMs` 再次 `OpenAsync`。
- HSL 12.8.3 里不少 `*Async` 内部是 `Task.Run` 包同步实现，管道基类和串口就是这样。模板的公开方法调用这些异步 API。
- `RawDevice` 返回底层 `DeviceCommunication`。本类没有包装的 HSL 方法从这里调用。
- `Ping()` 同步调用 `DeviceTcpNet.IpAddressPing`，用来区分网线问题和端口问题。
- `EnablePersistentConnection()` 同步调用 `SetPersistentConnection`。个别协议不支持时忽略异常。

除 `IPlcClient` 已有的方法外，基类还提供：

`ReadByteAsync`、`ReadBytesAsync`、`ReadInt16Async`、`ReadInt16ArrayAsync`、`ReadUInt16Async`、`ReadUInt16ArrayAsync`、`ReadInt32ArrayAsync`、`ReadUInt32Async`、`ReadUInt32ArrayAsync`、`ReadInt64Async`、`ReadUInt64Async`、`ReadFloatAsync`、`ReadFloatArrayAsync`、`ReadDoubleAsync`、`ReadDoubleArrayAsync`、`ReadStructAsync<T>`。

写：`WriteBoolArrayAsync`、`WriteByteAsync`、`WriteBytesAsync`、`WriteInt16Async`、`WriteUInt16Async`、`WriteUInt32Async`、`WriteInt64Async`、`WriteUInt64Async`、`WriteFloatAsync`、`WriteDoubleAsync`，以及 `WriteStringAsync(address, value, length)` 定长写。

`DeviceCommunication` 没有按字节写的重载。`WriteByteAsync` 调用 `WriteAsync(address, (short)value)`。

等待：`WaitBoolAsync`、`WaitWordAsync`、`WaitInt32Async`。成功时 `Value` 是耗时。内部检查间隔 20 ms，超时参数由调用方传入。

`TryReadAsync`、`TryWriteAsync`、`TryCallAsync` 是 `protected`，子类自定义读写时复用连接守卫和串行门闩。

## 3. PLC 工厂和型号

`HslDeviceFactory.Create(PlcConfig)` 按 `Protocol` 创建客户端，不认识的协议抛 `NotSupportedException`。`TryCreate` 把异常收成 false 和错误文本。`Program` 在 `TryCreate` 失败时退回 `Siemens7Client`。

协议名不区分大小写，并接受这些别名：

| 配置值 | 类型 | 端口缺省 |
|---|---|---|
| `SiemensS7`、`Siemens`、`S7`、空字符串 | `Siemens7Client` | 102 |
| `ModbusTcp`、`Modbus` | `ModbusTcpClient` | 502 |
| `InovanceTcp`、`Inovance` | `InovanceTcpClient` | 502 |
| `DeltaTcp`、`Delta` | `DeltaTcpClient` | 502 |
| `MelsecMc`、`Melsec`、`Mc` | `MelsecMcClient` | 6000 |
| `OmronFins`、`Omron`、`Fins` | `OmronFinsClient` | 9600 |

Modbus 站号被限制在 1～247。

`PlcDeviceCatalog.All` 是配置页的型号清单：显示名、协议、CPU、默认端口、是否显示机架插槽或站号、地址提示。新增一种界面可选的 PLC 时，加一个 `HslDeviceBase` 子类，在 `Create` 里加分支，并在 `All` 里加一条 `PlcDeviceDescriptor`。配置页读取这份清单，不必再改一处下拉框。

各客户端构造函数：

```csharp
new Siemens7Client(ip, port: 102, cpuType: "S1200", connectTimeoutMs: 2000, receiveTimeoutMs: 2000, rack: 0, slot: 0);
new ModbusTcpClient(ip, port: 502, station: 1, connectTimeoutMs: 2000, receiveTimeoutMs: 2000);
new InovanceTcpClient(ip, port: 502, station: 1, connectTimeoutMs: 2000, receiveTimeoutMs: 2000);
new DeltaTcpClient(ip, port: 502, station: 1, connectTimeoutMs: 2000, receiveTimeoutMs: 2000);
new MelsecMcClient(ip, port: 6000, connectTimeoutMs: 2000, receiveTimeoutMs: 2000);
new OmronFinsClient(ip, port: 9600, node: 0, connectTimeoutMs: 2000, receiveTimeoutMs: 2000);
```

西门子 CPU 字符串：`S1500`/`1500`、`S300`/`300`、`S400`/`400`、`S200Smart`/`200Smart`，其他值按 S7-1200。额外方法：`ReadDateTimeAsync`、`WriteDateTimeAsync`、`ReadOrderNumberAsync`。底层对象是 `S7`，也可以用 `RawDevice`。

Modbus 家族（通用、汇川、台达）继承 `ModbusClientBase`，额外有 `ReadCoilAsync`、`ReadDiscreteAsync`、`WriteOneRegisterAsync`、`WriteMaskAsync`。底层对象是 `Modbus`。地址按 HSL 的写法：保持寄存器 `"0"` / `"100"`，线圈配合 `ReadCoilAsync` 或 `"coil=0"`，离散输入 `"dis=0"`，输入寄存器 `"x=3;0"`。汇川和台达的 D 区按保持寄存器编号写。

三菱地址用 `D100`、`M100`、`X0`、`Y0`、`W100`。底层对象是 `Mc`。

欧姆龙：`SA1` 固定为 1。`node > 0` 时 `DA1` 取该值（最大 254）；`node <= 0` 时取 IP 最后一段，解析失败则用 1。实际节点号见属性 `Node`。底层对象是 `Fins`。

### 仿真 PLC

`AppConfig.Simulate` 为 true 时，`Program` 不走工厂，而是 `new FakePlcClient(commandAddress)`。`commandAddress` 来自地址表的 `PLC_指令`，缺失时用 `MW200`。`SimulateStepSeconds > 0` 时调用 `StartAutoFlow`，默认循环 10、20、30、40、0。

`FakePlcClient` 实现 `IPlcClient`，内存里按地址保存值。测试或步骤里可以用 `SetWord`、`SetWords`、`SetBool`、`SetBoolArray`、`SetString`、`GetString`。`FailOpen` 为 true 时 `OpenAsync` 失败。它没有 `RawDevice`。

## 4. 传输对象

PLC 走 `HslDeviceFactory`。TCP、UDP、串口、通用 HTTP 和 Open Protocol 不进 `plc.xml`，由调用方在需要时创建。入口是 `HslTransportFactory`：

```csharp
HslTransportFactory.CreateTcp(ip, port, timeoutMs: 2000);
HslTransportFactory.CreateUdp(ip, port, timeoutMs: 2000);
HslTransportFactory.CreateSerial(portName, baudRate: 9600, dataBits: 8, stopBits: StopBits.One, parity: Parity.None, timeoutMs: 2000);
HslTransportFactory.CreateHttp(host, port: 80, timeoutMs: 5000);
HslTransportFactory.CreateHttpServer();
HslTransportFactory.CreateOpenProtocol(ip, port: 4545, timeoutMs: 2000, revisionOnConnected: 1);
HslTransportFactory.CreateOpenProtocolServer();
```

也可以直接 new 下面的类型。未连接时，管道的发送和接收返回失败并保持未连接，不在读写里隐式重连。发送或接收失败后会把通道标成断开并关闭管道，下一次要再次 `OpenAsync`。

### TCP

`HslTcpClient` 继承 `HslPipeChannel`，包在 HSL `PipeTcpNet` 上。构造：

```csharp
new HslTcpClient(ip, port, timeoutMs: 2000);
new HslTcpClient(name, ip, port, timeoutMs);
```

`OpenAsync` 调用 `OpenCommunicationAsync`，`SendAsync` 调用 `SendAsync`，`ReceiveAsync` 调用长度为负的 `ReceiveAsync`（只取当前一包），`ReceiveExactAsync` 调用正长度重载并一直读到凑满或超时，`CloseAsync` 调用 `CloseCommunicationAsync`。`RawTcp` 或 `RawPipe` 是原始管道。

`TcpDeviceBase` 是空的抽象子类，给需要自己组帧的设备使用。连接和收发已经在基类里。模板没有单独的打印机、扫码枪或 TCP 服务端类型。带 HSL 报文头的 `ReadFromCoreServerAsync` 不在这个客户端里。

### UDP

`HslUdpClient` 同样继承 `HslPipeChannel`，包在 `PipeUdpNet` 上。打开、发送、接收与 TCP 相同。`RawUdp` 是原始管道。这里不包装 `HslCommunication.Enthernet.NetUdpClient`。

### 串口

`HslSerialClient` 包在 `PipeSerialPort` 上。`SerialPortInni` 在构造时执行，失败则 `OpenAsync` 直接返回该错误。公开的打开和收发使用管道上的异步方法。HSL 12.8.3 的 `DeviceSerialPort.Open` 只有同步方法；管道异步实现内部会进入串口的同步打开和发送。`DeviceSerialPort` 是按地址读写的另一套基类，本类型不继承它。`RawSerial` 是 `PipeSerialPort`。

### HTTP 客户端

`HslHttpClient` 包在 `NetworkWebApiBase` 上，给工站直接访问一台设备或服务：

```csharp
new HslHttpClient(host, port: 80, timeoutMs: 5000);
new HslHttpClient(host, port, userName, password, timeoutMs: 5000);
```

`userName` 为空时不带用户名。方法：`GetAsync(rawUrl)`、`PostAsync(rawUrl, body)`、`RequestAsync(HttpMethod, rawUrl, body, contentType)`，返回 `DeviceResult<string>`。`RawClient` 用来改内容类型、HTTPS 或请求头。`Dispose` 释放内部的 `HttpClient`。

MES 过站、重试和「接口关闭时放行」只存在于 `HttpApiClient`。

### HTTP 服务

`HslHttpServer` 包在 HSL `HttpServer` 上。12.8.3 只有同步的 `Start(int)`、`Start(string)` 和 `Close`，没有 `StartAsync`。本类的 `StartAsync` / `StopAsync` 调用的就是这些同步方法，调用前检查取消令牌。

```csharp
var server = HslTransportFactory.CreateHttpServer();
server.HandleRequest = (request, response, body) => "ok";
server.IsCrossDomain = true;
var started = await server.StartAsync(8080);
await server.StopAsync();
```

`StartAsync(int)` 监听 `http://+:端口/`。`StartAsync(string prefix)` 使用调用方给的前缀。HSL 的前缀重载不更新自己的 `Port`，本类从 URL 解析并记在 `Port` 上。`HandleRequest` 对应 `HandleRequestFunc`，返回值作为响应正文，返回 null 时 HSL 不写正文。`RawServer` 用来注册 RPC、跨域和日志。`StopAsync` 和 `Dispose` 都调用 `Close()`。

### Open Protocol 客户端

`HslOpenProtocolClient` 包在 `OpenProtocolNet` 上，默认端口 4545。`OpenAsync` 调用 `ConnectServerAsync`，`CloseAsync` 调用 `ConnectCloseAsync`。未连接时 `ReadCustomerAsync` 直接失败。

```csharp
var gun = HslTransportFactory.CreateOpenProtocol("192.168.0.20", 4545, timeoutMs: 2000, revisionOnConnected: 1);
await gun.OpenAsync();
gun.MessageReceived += (sender, args) => { };
var text = await gun.ReadCustomerAsync(mid, revision, stationId, spindleId, parameters);
```

`ReadCustomerAsync` 的 `revision` 参数对应 HSL 里拼写为 `revison` 的参数。`MessageReceived` 转发 `OnReceivedOpenMessage`。`RawDevice` 是 `OpenProtocolNet`。

HSL 12.8.3 的 `JobMessage`、`TighteningResultMessages`、`ToolMessages`、`TimeMessages`、`ParameterSetMessages` 只有同步方法。本客户端不包装它们，需要时用 `RawDevice`。

### Open Protocol 服务

`HslOpenProtocolServer` 包在 `OpenProtocolServer` 上。12.8.3 的 `ServerStart`、`ServerClose`、`Publish`、`SetVinNumber` 都是同步方法。`StartAsync(port)` 调用 `ServerStart`，`StopAsync` 调用 `ServerClose`。`IsStarted` 和 `Port` 读自底层对象。

```csharp
var server = HslTransportFactory.CreateOpenProtocolServer();
var started = await server.StartAsync(4545);
server.SetVinNumber(vin);
server.Publish(mid, revision, stationId, spindleId, parameters);
await server.StopAsync();
```

`Publish` 的 `revision` 同样对应库里的 `revison`。`StopAsync` 和 `Dispose` 都会 `ServerClose`。关闭时还会停掉该服务对象里的私有定时器，否则对象会被定时器一直抓住。
