# 更新与打包

主机怎么选择和安装版本，以及怎么把程序打成 Velopack 全量包。后端的目录和 HTTP 路径见 [HostTemplate.Backend](../src/HostTemplate.Backend/README.md)。配置目录见 [配置](配置.md)。

## 1. 版本号

`Directory.Build.props` 固定主版本 1、次版本 0。`VersionPatch` 为空时补丁是 0，本地构建得到 `1.0.0`。`AssemblyVersion` 和 `FileVersion` 是 `1.0.<补丁>.0`。

CI 传入 `VersionPatch`（GitHub `run_number`）和 `SourceRevisionId`（提交号前 7 位）。有 `SourceRevisionId` 时，信息版本是 `1.0.N+<7位提交号>`。界面标题和右下角用 `AppVersion.FormatDisplay`：没有加号时显示整段信息版本，有加号时提交号只留 7 位。比较版本时丢掉 `+` 后面的提交号和 `-` 后面的后缀。

版本号不写回仓库。安装包放在运行器临时目录或本地的 `artifacts/`，不提交进 git。

## 2. 主机侧更新

`Program` 在 `Main` 开头调用 `VelopackApp.Build().SetAutoApplyOnStartup(false).Run()`，避免 Velopack 在启动瞬间自己重启。是否安装由 `StationUpdateController` 决定。

服务地址和工站编号来自 `bootstrap.xml`。`StationId` 为空时用 `app.xml` 的 `EquId`。令牌放在 `HttpClient` 的 `X-Host-Token` 上，Velopack 下载 feed 和 nupkg 时也带这个头（`TokenFileDownloader`）。

空闲的定义在 `StationEngine.IsIdle`，也就是 `StationIdle.Evaluate`：流程字为 0，`Testing` 为 false，`RunningStep` 为空，且没有步骤正在执行。地址表不参与判断。主界面不自己拼这个条件。

### 手动选择

「程序更新」调用 `GET /api/stations/{id}/versions`，用 `UpdateForm` 列出全部版本。`latest` 是当前策略选中的目标。操作员选定后要再确认一次。取消则不下载、不安装。

所选版本与当前显示版本相同时报「当前已经是版本 …」。比当前低的版本按回退确认，比当前高的按安装确认。确认后按该版本的 `feedUrl` 下载。Velopack 选项是通道 `win`，`AllowVersionDowngrade = true`。

下载完成后若工站空闲，立刻 `ApplyAndRestart`。不空闲时提示「工站正在生产，版本 … 已下载，将在空闲后安装并重启」。主界面每 300 ms 调用一次 `TickAsync`，变为空闲后再安装。

当前进程不是 Velopack 安装（例如 `dotnet run`，或只解压了 zip）时，控制器返回「当前程序不是 Velopack 安装包，不能替换程序文件。」窗口上的版本号照常显示。

### 自动更新

`app.xml` 的 `AutoUpdate` 为 true，且已经配置了服务地址和工站编号时，`TickAsync` 按 60 秒间隔调用 `GET /api/stations/{id}/latest`。第一次界面刷新就会查询。只有返回的版本比当前新时才下载（`AppVersion.IsNewer`）。自动更新只看这个接口返回的版本。下载之后等空闲才安装。

已经有一个待安装版本时，跳过自动查询。当前进程不是 Velopack 安装时不下载，并只记录一次「当前程序不是 Velopack 安装包，不能替换程序文件。」

`latest` 的 JSON 含 `version`、`policy`、`feedUrl`、`downloadUrl`、`fileName`、`size`、`publishedAt`。`Program.cs` 注册的策略是 `NewestVersionPolicy`，`policy` 为 `newest`，在全部已发布版本里取版本号最大的一个，不按工站区分。`IVersionPolicy.Select(stationId, packages)` 是替换点。主机按返回的 `version` 和 `feedUrl` 下载。

## 3. 打包脚本

`scripts/pack-velopack.ps1` 把已经编译好的程序目录打成 Windows 全量包。路径相对仓库根（`scripts` 的上一级）。传入绝对路径时直接使用该路径，不拼到仓库根目录。GitHub Actions 可以把 `RUNNER_TEMP` 下的目录传进来。

脚本在非 Windows 上直接失败。Linux 上的 `vpk` 只会产出 AppImage，不能给 Windows 工控机用。Windows 包以 `.github/workflows/release.yml` 为准。

`vpk` 放在仓库根的 `.tools`（已在 `.gitignore`）。本机还没有 `vpk.exe` 时，脚本执行 `dotnet tool update vpk --tool-path .tools --version 0.0.1298`。调用参数固定包含 `--channel win --delta None`，产出 `*-full.nupkg` 和 `releases.win.json`。失败时打印异常信息并以退出码 1 结束。

| 参数 | 默认 | 含义 |
|---|---|---|
| `-SourceDir` | `src/HostTemplate.App/bin/Release/net8.0-windows` | 已编译或已发布的程序目录。`-PublishDir` 是它的别名 |
| `-OutputDir` | `artifacts/velopack` | Velopack 输出目录，已在 `.gitignore` |
| `-PackId` | `HostTemplate` | 包名，nupkg 文件名用它 |
| `-MainExe` | `HostTemplate.exe` | 入口程序，必须在打包目录里 |
| `-PackTitle` | `HostTemplate` | 显示名 |
| `-PackAuthors` | `装备开发部` | 作者 |
| `-Version` | 交互式询问 | 形如 `1.0.42`。非交互时必须传入 |
| `-Include` | 空 | 相对源目录的文件、目录或通配符。空则打包源目录里的文件 |
| `-Exclude` | 根上的 `app.xml`、`plc.xml`、`api.xml`、`users.xml`、`bootstrap.xml` | 只在没传 `-Include` 时生效，且只排除源目录根上的这些文件名。`templates\` 下的同名文件会保留 |
| `-NonInteractive` | 关 | 不 `Read-Host`、不暂停。环境变量 `GITHUB_ACTIONS` 或 `CI` 为 `true` 时同样不提问 |
| `-Force` | 关 | 非交互时版本已存在，必须加这个才覆盖 |

不传 `-Include`、且源目录根上没有那些被排除的文件时，直接把源目录交给 `vpk`。根上有工站配置，或指定了 `-Include`，会先复制到临时目录再打包，结束时删除临时目录。`-Include` 一个都匹配不到时，脚本失败。

交互式会扫描输出目录里的 `RELEASES`、`releases*.json` 和 `*.nupkg`，列出已有版本。有版本时建议下一个补丁号，回车接受。没有已有版本时建议 `1.0.0`。该版本已经存在时询问 `y/N`，默认不覆盖。交互结束前会 `pause`。

先发布再打包的例子（在仓库根）：

```powershell
dotnet publish src/HostTemplate.App/HostTemplate.App.csproj -c Release

pwsh ./scripts/pack-velopack.ps1
```

指定目录：

```powershell
pwsh ./scripts/pack-velopack.ps1 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack
```

CI 或不提问：

```powershell
pwsh ./scripts/pack-velopack.ps1 `
  -Version 1.0.42 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack `
  -NonInteractive
```

只打包列出的文件时，列表要包含主程序和它依赖的 dll，否则包能打出来但不能运行：

```powershell
pwsh ./scripts/pack-velopack.ps1 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack `
  -Include HostTemplate.exe,HostTemplate.dll,log4net.config,bootstrap.default.xml,templates/app.xml,templates/plc.xml,templates/api.xml `
  -Version 1.0.3 `
  -NonInteractive
```

## 4. GitHub Release

`.github/workflows/release.yml` 在推送到 `main` 时，于 `windows-latest` 上执行：

1. 安装 .NET 8 SDK。
2. `dotnet test HostTemplate.sln -c Release`，并传入 `VersionPatch` 为 `github.run_number`、`SourceRevisionId` 为提交号前 7 位。
3. `dotnet publish src/HostTemplate.App/HostTemplate.App.csproj -c Release` 到运行器临时目录。
4. 核对 `HostTemplate.exe` 的 `FileVersion` 为 `<版本>.0`，并在 `HostTemplate.dll` 里能找到信息版本 `<版本>+<7位提交号>`。
5. 把发布目录压成 `HostTemplate-<版本>.zip`。
6. 调用 `scripts\pack-velopack.ps1 -Version <版本> -PublishDir <发布目录> -OutputDir <feed目录> -NonInteractive`。
7. 创建或更新 GitHub Release，标签 `v1.0.<run_number>`，标题 `HostTemplate <版本>`。附件是 zip、`*-full.nupkg` 和 `releases.win.json`。

把 Release 上的 `HostTemplate-<版本>-full.nupkg` 放到后端的 `data/inbox`，或 `PUT /api/packages/<版本>`。服务自己生成每个版本的 feed。操作步骤见后端 README。
