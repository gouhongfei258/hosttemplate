# HostTemplate 开发手册

现场怎么下载、解压和操作，写在仓库根的 [README](../README.md)。配置目录和更新规则的现场说明在 [配置与更新](config-and-updates.md)。这里只写开发和打包。

主界面只负责显示和把按钮交给引擎。业务在 `StationEngine` / `IStationStep`。配置先用本地，本地没有再问后端，后端也没有才从模板生成。手动拉远端配置必须确认后才覆盖。程序更新只走 `HostTemplate.Backend`。自动更新下载之后，也要等工站空闲才安装。

## 1. 技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| 运行时 | .NET 8（`net8.0-windows`） | SDK 式 csproj，`x64` |
| UI | WinForms + SunnyUI 3.7.2 | SunnyUI 有 `net8.0-windows7.0` 目标 |
| PLC | HslCommunication 12.8.3（NuGet） | 不要再用 `using/HslCommunication.dll`，那是 net48 专用编译版 |
| 数据 | EF Core 8.0.1 + Microsoft.Data.Sqlite | 替代 EF6 + SQLite.CodeFirst（不支持 .NET 8） |
| 日志 | log4net 3.3.0 | 落盘 + 事件推送界面（3.0.3 有 CVE-2026-40021，必须 ≥ 3.3.0） |
| 配置 | XML + `XmlSerializer` + `PropertyGrid` | 现场可直接改、可可视化编辑 |
| 测试 | xunit | 引擎、配置、轨迹、落库、鉴权、设备、实时数据、配置加载顺序、更新 |

## 3. 本地运行

```bash
# 无硬件，仿真 PLC：每 3 秒推进一次流程字，并自动开始监控
dotnet run --project src/HostTemplate.App -- --simulate --autostart

# 本线后端
dotnet run --project src/HostTemplate.Backend --urls http://0.0.0.0:5080

dotnet test HostTemplate.sln
```

| 参数 | 作用 |
|---|---|
| `--simulate` | 强制启用仿真 PLC，并把自动推进间隔设为 3 秒 |
| `--autostart` | 窗口显示后自动开始监控 |
| `--config` | 直接打开配置编辑页，保存后退出 |

接真实 PLC 时把 `app.xml` 的 `Simulate` 改为 `false`，然后在「系统配置 → PLC 连接」里选型号、填 IP，点「连接测试」通了再保存。

从这份模板改成另一个工站名：在仓库根执行 `.\init.ps1 -Name "MyStation" -Title "某产线某工站"`。脚本会改命名空间、项目名、打包脚本和发布工作流里的 `HostTemplate`。

## 4. 引擎

`StationEngine` 在 `Flow/Engine`。

- **边沿触发**：流程字与上次处理值不同才分发，PLC 抖动不会重复执行。
- **单飞防重入**：上一步未结束时不重入，且不丢弃，下一轮继续尝试。
- **统一回写**：步骤返回 `StepResult`，引擎负责写审查码、记轨迹、统计良率。
- **失败不阻断**：通信失败只置报警并断开，下一轮按重连间隔再试。HSL 客户端本身不会在一次读写里偷偷重连。
- **地址解耦**：引擎只认 `AddressKeys` 里的键名，换点位只改 `plc.xml`。
- **不管画面**：引擎不填写实时页面。产品结论怎么画由工站自己的控件决定。程序报警走 `AlarmManager`，主界面只负责把报警条亮出来。

### 主界面

上半部分是工站身份：顶栏状态灯，下面是流程字 / SN / 托盘 / 轨迹 / 良品不良计数。中间是两个页签，底栏按钮不动。

| 区域 | 谁负责 |
|---|---|
| 报警条 | 模板。在身份条和页签之间，始终可见 |
| 实时数据 | 工站整页自己写。`MainForm` 只把它 Dock 满这一页 |
| 运行日志 | 模板 |

在 `Program.cs` 里把控件交进去。`DemoLiveView` 只是示例，换掉这一行即可，不用改引擎：

```csharp
var realtimeView = new MyStationView();
Application.Run(new MainForm(context, engine, realtimeView, CreatePlcClient, CreateApiClient));
```

`CycleLiveData` 是可选的数据袋，不是页面契约。示例工站用它推测试项、曲线点和产品结论，并在进站时自己 `BeginCycle()`。不做历史查询页，落库仍走 `TestDataStore`。

```csharp
context.Live.BeginCycle();
context.PublishItem("电压", "11.5 ~ 12.5", "12.01", true);
context.PublishPoint("电压曲线", t, 12.01);
context.PublishVerdict(true, "合格");
```

顶栏「日间 / 夜间」会换整窗颜色。示例页实现了 `IMainThemeAware`。选择写入 `app.xml` 的「界面主题」，默认夜间。

## 5. 新增一个工站步骤

```csharp
using HostTemplate.Core.Flow.Engine;
using HostTemplate.Core.Flow.Process;

public sealed class MyLeakTestStep : IStationStep
{
    public ushort Word => ProcessWords.TestStart;   // 20
    public string Name => "气密性检测";

    public async Task<StepResult> ExecuteAsync(StepContext ctx)
    {
        var ok = await RunLeakDeviceAsync(ctx.CancellationToken);
        return ok
            ? StepResult.Ok(ReviewCode.OK_TestStart)
            : StepResult.Ng(ReviewCode.NG_TestStart, "泄漏量超上限");
    }
}
```

在 `DemoSteps.Create()` 里注册即可，不需要改引擎。

## 6. 配置三件套

| 文件 | 内容 | 关键字段 |
|---|---|---|
| `app.xml` | 机器/工站/运行参数 | `EquId`、`PollIntervalMs`、`HeartbeatTicks`、`RequiredSteps`、`Simulate`、`Theme`、`AutoUpdate` |
| `plc.xml` | 连接参数 + 地址表 | `Protocol`、`Address`、`Port`、`CpuType`、`Rack`、`Slot`、`StationNo`、`Addresses[]` |
| `api.xml` | 上位系统接口 | `BaseUrl`、`Headers[]`、`Endpoints[]`、`Enabled` |

`DatabasePath` 若是相对路径，相对配置目录而不是程序目录。加载顺序、手动覆盖和自动更新见 [配置与更新](config-and-updates.md)。

默认地址表（可在 `ConfigManager.CreateDefaultPlc()` 中调整）：

| 键名 | 方向 | 默认地址 | 类型 |
|---|---|---|---|
| `MES_心跳` | 写 | M100.0 | Bool |
| `PLC_指令` | 读 | MW200 | Word × 2 |
| `PLC_预留bool` | 读 | M110.0 | Bool × 16 |
| `MES_审查结果` | 读写 | MW210 | Word |
| `MES_SN` | 写 | DB1.DBB0 | String(20) |
| `PLC_SN` | 读 | DB1.DBB100 | String(20) |
| `PLC_托盘号` | 读 | MW220 | Word |

## 7. 配置编辑页

主界面点「系统配置」（或 `--config` 启动）打开，四页：基础参数、PLC 连接、PLC 地址表、MES 接口。

PLC 连接页的数据源只有 `PlcDeviceCatalog`（`HostTemplate.Devices.Hsl`）。下拉框、行显隐、默认值、说明文字、校验规则都读它，没有第二处硬编码。新增一个型号只要往 `All` 里加一条。

型号（10 项）：

| 型号 | 协议 | 默认端口 | 显示的行 |
|---|---|---|---|
| 西门子 S7-1200 / 1500 / 300 / 400 | `SiemensS7` | 102 | IP / 端口 / 机架 / 插槽（200 Smart 无机架插槽） |
| 西门子 S7-200 Smart | `SiemensS7` | 102 | IP / 端口 |
| Modbus TCP（通用） | `ModbusTcp` | 502 | IP / 端口 / 站号 |
| 汇川 Inovance（AM/H5U） | `InovanceTcp` | 502 | IP / 端口 / 站号 |
| 台达 Delta（DVP/AS） | `DeltaTcp` | 502 | IP / 端口 / 站号 |
| 三菱 MC（Q/FX5U/iQ-R） | `MelsecMc` | 6000 | IP / 端口 |
| 欧姆龙 FINS（NJ/NX/CJ） | `OmronFins` | 9600 | IP / 端口 / 节点号 |

选中型号后：按 `UseRackSlot` / `UseStation` 显隐行，填该型号的默认端口和站号，右边给出说明，底部提示地址写法。S7-300/400 插槽默认 2，S7-1200/1500 默认 0。欧姆龙节点号留 0 时，客户端取 IP 末段。

「连接测试」用当前页面上的参数连一次，不使用已保存的值。连上了且地址表有 `PLC_指令` 就再读一次。连不上会再 Ping 一次，区分网线和端口问题。测试在 `Task.Run` 里跑，测完立即 `Dispose`。

三个约定：

1. **改的是副本**：打开时 `XmlConfigStore.Clone` 深拷贝，点「取消」原配置不动。
2. **保存前校验**：轮询周期、端口、CPU 型号、键名重复、地址为空、缺 `PLC_指令` 等。出错会跳到那一页。
3. **保存即生效**：主窗 `ApplyConfigAsync()` 停监控，重读三份 XML，用工厂重建客户端，`engine.ReloadAddresses()`，再恢复运行。

不阻断保存的提醒会单独弹窗：地址表缺键名、开着仿真模式、打开了登录开关。

## 8. 设备层

HSL 12.x 的公开读写方法几乎都挂在 `DeviceCommunication` 上。封装按「怎么连」分层，不按品牌各写一套。

| 位置 | 类型 | 作用 |
|---|---|---|
| `Devices/Hsl/HslDeviceBase` | `HostTemplate.Devices.Hsl` | 连接守卫、串行锁、全类型同步读写，实现 `IPlcClient` |
| `Devices/Hsl/HslDeviceFactory` | 同上 | 按 `plc.xml` 的 `Protocol` 创建客户端 |
| `Devices/Hsl/PlcDeviceCatalog` | 同上 | 型号元数据：默认端口、显示哪些行、地址写法 |
| `Devices/Plc/Modbus` | `HostTemplate.Devices.Plc.Modbus` | `ModbusClientBase`，以及 Modbus / 汇川 / 台达 |
| `Devices/Plc/Siemens` | `HostTemplate.Devices.Plc.Siemens` | S7。只保留建 `SiemensS7Net`、读时钟、读订货号 |
| `Devices/Plc/Melsec` | `HostTemplate.Devices.Plc.Melsec` | 三菱 MC，默认 6000 |
| `Devices/Plc/Omron` | `HostTemplate.Devices.Plc.Omron` | FINS，默认 9600 |
| `Devices/Plc/Simulation` | `HostTemplate.Devices.Plc.Simulation` | `FakePlcClient`，不连硬件 |
| `Devices/Api` | `HostTemplate.Devices.Api` | 端点表驱动的 HTTP 客户端 |
| `Devices/Tcp` | `HostTemplate.Devices.Tcp` | 打印机、扫码枪、仪器的 TCP 基类 |

读写是同步的，全部 `bool + out`，不抛异常：`Bool / Byte / Bytes / Int16 / UInt16 / Int32 / UInt32 / Int64 / UInt64 / Float / Double / String / 数组 / ReadStruct<T>`。另外有 `WaitBool`、`Ping`、`EnablePersistentConnection`、`RawDevice`。客户端不会在失败时自己重连，下一轮由引擎决定。

`ModbusClientBase` 另有 `ReadCoil / ReadDiscrete / WriteOneRegister / WriteMask`。

加一个新品牌（基恩士 MC 为例），类放在 `Plc/Keyence`，命名空间 `HostTemplate.Devices.Plc.Keyence`：

```csharp
public sealed class KeyenceMcClient : HslDeviceBase
{
    public KeyenceMcClient(string ip, int port = 5000)
    {
        Name = "KeyenceMc";
        Address = ip;
        var mc = new KeyenceMcNet(ip, port);
        Device = mc;
        ConnectAction = () => mc.ConnectServer();
        CloseAction = () => mc.ConnectClose();
    }
}
```

然后两步接完：

1. `HslDeviceFactory.Create()` 加一个 `case`。
2. `PlcDeviceCatalog.All` 加一条型号。

不需要改配置页，也不需要动 `HslDeviceBase`。HSL 的 `XxxAsync` 在多数设备上只是同步包装，主循环是定时轮询，所以这里不包一层异步。需要时直接用 `RawDevice` 或 `Task.Run`。

## 9. 登录与权限

`app.xml` 的「启用登录」默认 `false`。关闭时 `StationContext.Session` 是匿名管理员，所有权限判断放行。

打开后启动弹 `LoginForm`，账号存配置目录的 `users.xml`：

- 密码用 PBKDF2-SHA256（10 万次迭代 + 16 字节随机盐），比对走 `CryptographicOperations.FixedTimeEquals`。
- 首次自动生成 `admin / admin123`，并标记 `MustChangePassword`。
- 角色 `操作员 < 工程师 < 管理员`，判断用 `Session.HasRole(UserRole.工程师)`。
- 最后一个启用的管理员不能被停用、降级或删除。

```csharp
if (!context.Session.HasRole(UserRole.工程师)) { /* 拒绝 */ }
```

## 10. 从原项目迁移

1. **HslCommunication 换包**：原 `using/HslCommunication.dll` 只编译了 net48。必须用 NuGet `HslCommunication 12.8.3`。
2. **数据层重写**：EF6 和 `SQLite.CodeFirst` 不支持 .NET 8。已换成 EF Core + `EnsureCreated()`。
3. **`Global` 改名 `StationContext`**：叫 `AppContext` 会与 `System.AppContext` 冲突。所有模块通过构造函数注入。

## 12. 打包

脚本是 `scripts/pack-velopack.ps1`。它扫描输出目录里已有的 `RELEASES`、`releases*.json` 和 `*.nupkg`，建议下一个补丁版本，版本已存在时要确认才覆盖，然后调用 `vpk pack`。失败时会打印原因。vpk 放在仓库根的 `.tools`（已忽略），版本固定 `0.0.1298`。

路径相对仓库根目录（`scripts` 的上一级）。调用方传入绝对路径时原样使用，所以 GitHub Actions 可以把 `RUNNER_TEMP` 传进来。不要在脚本里写 `D:\...` 这种本机绝对路径。

默认：

| 参数 | 默认 | 含义 |
|---|---|---|
| `-SourceDir` | `src/HostTemplate.App/bin/Release/net8.0-windows` | 已编译或已发布的程序目录。`-PublishDir` 是它的别名 |
| `-OutputDir` | `artifacts/velopack` | Velopack 输出目录，已在 `.gitignore` |
| `-PackId` | `HostTemplate` | 包名，nupkg 文件名用它 |
| `-MainExe` | `HostTemplate.exe` | 入口程序，必须在打包目录里 |
| `-PackTitle` | `HostTemplate` | 显示名 |
| `-PackAuthors` | `装备开发部` | 作者 |
| `-Version` | 交互式询问 | CI 必须传入，例如 `1.0.42` |
| `-Include` | 空 | 相对源目录的文件列表。空则打包整个源目录 |
| `-Exclude` | 根上的 `app.xml`、`plc.xml`、`api.xml`、`users.xml`、`bootstrap.xml` | 只在没传 `-Include` 时生效。`templates\` 下的同名模板会保留 |
| `-NonInteractive` | 关 | 不 `Read-Host`、不暂停。`GITHUB_ACTIONS` 或 `CI` 为 true 时同样不提问 |
| `-Force` | 关 | 非交互时版本已存在，必须加这个才覆盖 |

不传 `-Include` 时，如果源目录根上没有那些工站配置，就直接把源目录交给 `vpk`，避免再复制一遍发布输出。有工站配置，或指定了 `-Include`，会先复制到临时目录再打包，打完删掉临时目录。

本地交互式（在仓库根，先 `dotnet publish` 或至少有一个带 `HostTemplate.exe` 的目录）：

```powershell
pwsh ./scripts/pack-velopack.ps1

pwsh ./scripts/pack-velopack.ps1 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack
```

回车接受建议的下一补丁号。该版本已经在输出目录里时，问 `y/N` 才覆盖。

CI 或不想提问：

```powershell
pwsh ./scripts/pack-velopack.ps1 `
  -Version 1.0.42 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack `
  -NonInteractive
```

只打包列出的程序文件（相对 `-SourceDir`）。列表里要包含主程序和它依赖的 dll，否则包能打出来但不能运行：

```powershell
pwsh ./scripts/pack-velopack.ps1 `
  -SourceDir src/HostTemplate.App/bin/Release/net8.0-windows `
  -OutputDir artifacts/velopack `
  -Include HostTemplate.exe,HostTemplate.dll,log4net.config,bootstrap.default.xml,templates/app.xml,templates/plc.xml,templates/api.xml `
  -Version 1.0.3 `
  -NonInteractive
```

`vpk` 参数固定为 `--channel win --delta None`，产出 `*-full.nupkg` 和 `releases.win.json`。Linux 上的 `vpk` 只会出 AppImage，脚本会直接拒绝。Windows 包以 `.github/workflows/release.yml` 为准。那条工作流在 `windows-latest` 上调用：

```powershell
scripts\pack-velopack.ps1 -Version $version -PublishDir $out -OutputDir $feedDir -NonInteractive
```

不要把 nupkg、zip 或 `artifacts/` 提交进仓库。

## 13. 后端

`src/HostTemplate.Backend` 是标准的 ASP.NET 项目：`Program.cs` 组装依赖，`Controllers` 暴露原来的 HTTP 路径，`Application` 放版本策略和 inbox 导入，`Infrastructure` 放文件库、feed 和令牌中间件，`Models` 放安装包记录和配置绑定。合同类型仍在 `HostTemplate.Contracts`。

接口、磁盘目录和 `dotnet run` 示例见 [Backend README](../src/HostTemplate.Backend/README.md)。

## 14. 合并后的 GitHub Release

`.github/workflows/release.yml` 在推送到 `main` 时，于 `windows-latest` 上用 .NET 8 跑测试，再 `dotnet publish` 到运行器临时目录。校验版本后打成 zip，并用打包脚本打 Velopack 全量包。创建 GitHub Release（标签 `v1.0.<run_number>`，说明里带短提交号），把 zip、nupkg 和 `releases.win.json` 挂到该 Release。不往仓库提交二进制。

版本不提交回仓库。`Directory.Build.props` 固定主次版本 `1.0`，补丁默认 `0`。CI 用 `github.run_number` 作为补丁，并把 7 位提交号写入 `InformationalVersion`（例如 `1.0.42+abcdef0`）。标签只用 `v1.0.42`。
