# HostTemplate 开发手册

给后续工站开发用。本文只写仓库里已经存在的类型、路径和行为。架构速览、PLC 型号表和 HSL 封装仍以 [README.md](../README.md) 为准，这里不另起一套。

代码以 `main` 为准。第 10 节的日间/夜间主题在 `main` 上还不存在，实现在未合并的 [PR #2](https://github.com/gouhongfei258/hosttemplate/pull/2)（分支 `cursor/day-night-theme-4667`）。合并前不要按那一节去调用 `IMainThemeAware` 或 `AppConfig.Theme`。

## 1. 这是什么

这是从 BYD DCS 上位机抽出来的 **C# / .NET 8 WinForms 工站宿主模板**。新工站在这上面接自己的步骤、实时画面和点位，而不是再复制一份几千行的流程过程。

技术栈（与工程文件一致）：

| 项 | 现状 |
|---|---|
| 运行时 | `net8.0-windows`，`PlatformTarget` 为 `x64`（`HostTemplate.App`）。Core / Devices / Tests 是 `net8.0` |
| UI | WinForms + SunnyUI 3.7.2 |
| PLC | HslCommunication 12.8.3（NuGet）。不要再引用 net48 的 `HslCommunication.dll` |
| 数据 | EF Core 8.0.1 + SQLite，`EnsureCreated()`，没有迁移 |
| 日志 | log4net 3.3.0 |
| 测试 | xunit。`tests/HostTemplate.Tests` 里 63 个 `[Fact]`，测的是 Core 和 Devices，不引用 App |

### 分层（必须遵守）

`MainForm` 的类注释写明：只做展示和指令下发。业务放在 `StationEngine` 分发到的 `IStationStep` 里。

- **`MainForm`**：状态灯、身份条、报警条、两个页签、底栏按钮。它不读业务点位，也不判断产品合格。
- **`StationEngine`**：轮询、心跳、边沿分发、回写审查码、记轨迹。类注释写明不含具体业务。身份条上的良品/不良按件记录，见第 6 节。
- **`IStationStep`**：一个流程字一个类。进站、测试、出站、和 MES/仪器的交互都写在这里。
- **`StationContext`**：构造函数注入的共享上下文，用来替换原来的静态 `Global`。不要再加静态全局状态。叫 `AppContext` 会和 `System.AppContext` 撞名。

引擎不管画面。产品结论画在工站自己的实时控件上。程序报警走 `AlarmManager`，主界面只负责把报警条亮出来。

│  ├─ Security/                  AuthService、UserAccount、UserSession
│  └─ Data/                      HostDbContext、TestDataStore、实体
├─ src/HostTemplate.Devices/     协议实现
│  ├─ Hsl/                       HslDeviceBase、各协议客户端、PlcDeviceCatalog、HslDeviceFactory

│  ├─ Api/                       HttpApiClient

### 从模板拉一个新工站

1. 以本仓库为起点（复制或在其上改）。程序集名是 `HostTemplate`，单实例互斥体是 `Global\HostTemplate-{8B0F2C11-4F0B-4A3E-9F0E-7A3F9C2D1E44}`。同一台机器要跑两个工站时，改互斥体名字，否则第二个进程会提示「程序已经在运行」并退出。
2. 改 `app.xml` 的工站号、工站名、产线（见第 8 节）。首次运行会在输出目录的 `config/` 下生成三份 XML。
3. 在 `Program.cs` 里把 `DemoSteps.Create(store)` 换成自己的步骤列表，把 `new DemoLiveView(...)` 换成自己的实时控件。这两处是工站入口，不必改 `StationEngine`。
4. 点位用 `AddressKeys` 的键名，绝对地址放在 `plc.xml`。引擎启动前地址表里必须有 `PLC_指令`。
5. 无硬件时：

```bash
dotnet run --project src/HostTemplate.App -- --simulate --autostart
```

| 参数 | 行为 |
|---|---|
| `--simulate` | 把 `App.Simulate` 置 true。若 `SimulateStepSeconds <= 0`，改成 3。然后走 `FakePlcClient` |
| `--autostart` | `MainForm.AutoStart = true`，窗口显示后调用 `engine.StartAsync()` |
| `--config` | 登录（若开启）之后直接弹出 `ConfigForm`，关掉即退出，不进主界面 |

`FakePlcClient.StartAutoFlow` 默认循环 `10 → 20 → 30 → 40 → 0`。`Program.cs` 只在 `SimulateStepSeconds > 0` 时启动自动推进；否则仿真 PLC 停在原地，等手动写流程字或点「复位流程」。

## 3. Program.cs 怎么把各块接上

`Main` 先抢互斥体，再 `ApplicationConfiguration.Initialize()`，然后 `InitLogger`，最后 `Run`。日志初始化失败会弹窗并返回，不进主流程。

`InitLogger`：

- 若输出目录有 `log4net.config`，用它配置 log4net。App 工程把该文件 `CopyToOutputDirectory`。
- 创建 `Log4NetLogger`。
- 挂上 `Application.ThreadException`、`AppDomain.UnhandledException`、`TaskScheduler.UnobservedTaskException`。未观察任务异常会被 `SetObserved()`。

`Run` 的顺序就是工站的组合根，不要把这段逻辑搬进 `MainForm`：

```csharp
// 1. 配置：<输出目录>/config 下的 app.xml、plc.xml、api.xml
var config = new ConfigManager(configDirectory);
config.Load(out var configMessage);

// 2. 上下文。Live、Alarms、State、Trace、Session 都在这里
var context = new StationContext(config, logger, baseDirectory);

// 3. 未启用登录则直接通过；启用则弹 LoginForm，取消则退出
// 4. --config 时只打开 ConfigForm

// 5. 设备
context.PlcClient = CreatePlcClient(context);   // Simulate → FakePlcClient，否则 HslDeviceFactory
context.ApiClient = CreateApiClient(context);   // HttpApiClient

// 6. 库。失败只记日志，不阻止启动
var store = new TestDataStore(context.DatabasePath);
store.EnsureCreated();

// 7. 引擎吃步骤列表，不吃界面
var engine = new StationEngine(context, DemoSteps.Create(store));

// 8. 实时页整页从这里交进去。换工站就换这一行
var realtimeView = new DemoLiveView(context.Live);
Application.Run(new MainForm(context, engine, realtimeView, CreatePlcClient, CreateApiClient)
{
    AutoStart = autoStart,
});
```

`MainForm` 额外收下两个工厂，是为了配置保存后能停监控、`ReloadConfig`、丢掉旧客户端、重建 PLC/API、`engine.ReloadAddresses()`、再按需重新 `StartAsync`。工厂可以不传，那时热加载不会重建通信对象。

`CreatePlcClient`：`HslDeviceFactory.TryCreate` 失败时记一条错误日志，并降级成 `Siemens7Client`（用 `plc.xml` 里的 IP、端口、CPU、超时、机架、插槽）。这是模板的退路，新协议应加进工厂，而不是靠这条降级。

## 4. 工站流程

### 4.1 流程字

`ProcessWords` 与现场 PLC 约定一致：

| 常量 | 值 | `Describe` |
|---|---|---|
| `Idle` | 0 | 等待进站 |
| `InStation` | 10 | 进站 |
| `TestStart` | 20 | 测试开始 |
| `TestFinish` | 30 | 测试结束 |
| `OutStation` | 40 | 出站 |
| `ReTest` | 50 | 复测 |

示例工站只注册了 10/20/30/40。`ReTest` 没有步骤。未注册的非 0 流程字：第一次打一条 Warn（`流程字 {n} 未注册处理步骤，已忽略。`），并视为已处理，不抛异常。0 不查找步骤、不告警。

自定义流程字可以：实现 `IStationStep.Word` 返回那个 `ushort`，放进交给引擎的列表。同一个字注册两次，构造 `StationEngine` 时抛 `InvalidOperationException`。

### 4.2 边沿分发

主循环在 `Task.Run` 里，周期是 `max(10, PollIntervalMs)`，默认 50 ms。每一轮：

1. `EnsureConnected`。未连接时按 `max(200, ReconnectDelayMs)` 节流再 `Open`。失败置报警「连接PLC失败」并保持 `PlcConnected = false`。
2. 每 `HeartbeatTicks` 次轮询翻转一次 `MES_心跳`（默认每 10 次）。地址为空则跳过。写失败置「写心跳失败」并 `Close`。
3. 读 `PLC_指令`，长度 2 个 Word，**只用 `words[0]`** 当作流程字。读失败置「读取流程字失败」并断开。
4. 写入 `State.ProcessWord` / `ProcessContent`。仅当「还没处理过」或「流程字和上次处理值不同」才 `DispatchAsync`。PLC 把同一个字握着不放，不会重复执行。
5. 读 `PLC_预留bool`。长度取地址表的 `Length`，缺省 16。有变化才触发 `ReserveBoolsChanged`。`MainForm` 没有订阅这个事件，工站要自己订。
6. 本轮没有抛异常时清除「PLC轮询异常」，状态设为 `正在监控`。

单飞：`SemaphoreSlim(1, 1)`，`WaitAsync(0)`。上一步还没结束就返回 `false`，**不更新**已处理流程字，下一轮再试，不丢这个字。

`StartAsync` 会清轨迹、清报警、把已处理流程字忘掉，然后起循环。地址表没有 `PLC_指令` 时不启动，状态 `系统异常`。`StopAsync` 取消循环、清空 `RunningStep`、`PlcConnected = false`、`PlcClient.Close()`。

进站（流程字 10）在调用步骤**之前**执行 `Trace.Clear()`。步骤正常返回（含 NG 的 `StepResult`）之后才 `Trace.Add`。所以进站步骤自己的 `ExecuteAsync` 里轨迹还是空的；测试开始里才能 `Check` 到 10。步骤抛异常时不记轨迹、不回写审查码、不改计数，置报警 `步骤异常:{步骤名}`，并把该流程字当成已处理。

### 4.3 IStationStep 与 StepResult

```csharp
public interface IStationStep
{
    ushort Word { get; }
    string Name { get; }
    Task<StepResult> ExecuteAsync(StepContext context);
}
```

步骤只通过 `StepContext` 碰 PLC、接口、日志、报警、状态和可选的 `Live`。不要在步骤里引用 `MainForm`。

```csharp
public static StepResult Ok(ReviewCode review, string message = "");
public static StepResult Ng(ReviewCode review, string message);
```

引擎拿到非 null 的结果后：

- `WriteReview`：`State.ReviewCode = (ushort)code`，再往 `MES_审查结果` 写一个 Word。地址为空则只改状态。写失败置「回写审查结果失败」。
- 打一条 ✔ / ✘ 日志，并触发 `StepExecuted`。

`StepResult.Success` 只表示这一步的审查结果。身份条良品/不良不按步骤次数累加，见第 6 节。

`StepContext.WriteReview` 是给步骤中途用的。它写 PLC 失败时**不**走 `AlarmManager`（引擎在步骤结束后的那次回写才会报警）。

### 4.4 ReviewCode

沿用原项目取值，PLC 判码不用改：

| 名称 | 值 | 名称 | 值 |
|---|---|---|---|
| `OK_InStation` | 1 | `NG_InStation` | 2 |
| `OK_TestStart` | 3 | `NG_TestStart` | 4 |
| `OK_TestFinish` | 5 | `NG_TestFinish` | 6 |
| `OK_OutStation` | 7 | `NG_OutStation` | 8 |
| `IsSample` | 9 | `NG_PowerReTest` | 10 |
| `OK_Done` | 20 | `NG_Product` | 30 |

约定是成对使用：进站成功回 `OK_InStation`，失败回 `NG_InStation`，其余步骤相同。`IsSample`、`NG_PowerReTest`、`OK_Done`、`NG_Product` 模板步骤没有用到，需要时直接作为 `StepResult` 的审查码即可。

`OK_*` / `NG_*` 只决定审查码和 `StepResult.Success`。它**不会**自动变成实时页上的产品 OK/NG。产品结论要自己 `PublishVerdict`（第 5 节）。

### 4.5 轨迹

`ProcessTrace.Add` 只在末尾去重（连续相同的字记一次）。`Text` 形如 `10-20-30-40`，主界面轨迹标签直接显示它。

`Check(required, out error)`：`required == null` 或里面的字都出现过则通过。**不要求顺序**，只要求包含。缺字时 `error` 会拼 `缺少流程 {n}（{中文名}）；`。

`app.xml` 的 `RequiredSteps` 默认 `10, 20, 30`。注释写明 40 是出站本身，不要放进这份清单。示例出站用的就是这份清单。

### 4.6 DemoSteps：照这个拆，然后换掉

`DemoSteps.Create(store)` 返回四个类：

| 类 | 字 | 实际做的事 |
|---|---|---|
| `DemoInStationStep` | 10 | `Live.BeginCycle()`，记下 `StartTime`，`Testing = true`。读 `PLC_SN`（长度 20）。仿真且 SN 为空时，按 `SnLength`（默认 18，小于等于 0 时按 18）造 `DEMOyyMMddHHmmss`，并尝试写到 `MES_SN`。长度不符则 `PublishVerdict(false, …)` 并 `NG_InStation`。通过则把 SN 写到 `State.SerialNumber` 和 `Live.RememberSerialNumber`，延迟 80 ms，返回 `OK_InStation`。MES 调用只留了注释，没有真正 `PostAsync` |
| `DemoTestStartStep` | 20 | 没有 SN，或轨迹里没有 10，则 `PublishVerdict(false)` 并 `NG_TestStart`。否则往曲线「示例电压」打两个点，延迟 120 ms，`OK_TestStart`。**不**调用 `PublishVerdict(true)` |
| `DemoTestFinishStep` | 30 | 结束计时，`Testing = false`。SN 含 `NG`（忽略大小写）则判不良，电压 13.6，否则 12.0。组 `TestDataRecord` + 一条「示例电压」测试项，`PublishItem`，再补两个曲线点，然后 `store.SaveAsync`。落库异常只置报警「测试数据落库失败」，不改变产品结论。`PublishVerdict(passed, message)`，再按成败返回 `OK_TestFinish` / `NG_TestFinish` |
| `DemoOutStationStep` | 40 | `Trace.Check(App.RequiredSteps)` 失败则 `PublishVerdict(false)` 并 `NG_OutStation`。通过则延迟 80 ms，清空 `State.SerialNumber` 和 `Testing`，返回 `OK_OutStation`。实时页上的 SN 靠 `RememberSerialNumber` 还在，因为出站没有 `BeginCycle` |

「SN 里带 NG 算不良」只存在于 `DemoTestFinishStep`，不是引擎规则。

`SnPrefix` 在 `AppConfig` 里有字段，示例进站**没有**用它。

`PLC_托盘号` 在默认地址表里，和 `PLC_SN`、`MES_心跳` 一样，只是一条可替换的 PLC 地址。地址表的作用是让现场改真实地址时不动代码。表里有这一项，并不要求引擎或主界面把它抄进 `StationState`。身份条若要显示托盘，显示的是 `State.TrayNo`；示例步骤没有给这个字段赋值，空着就显示 `--`。

### 4.7 添加或换掉步骤

引擎构造函数接受 `IEnumerable<IStationStep>`。保持示例结构时，改 `DemoSteps.Create` 的列表；整站替换时，在 `Program.cs` 直接传入自己的列表。不要改 `StationEngine`。

```csharp
public sealed class MyLeakTestStep : IStationStep
{
    public ushort Word => ProcessWords.TestStart;   // 20
    public string Name => "气密性检测";

    public async Task<StepResult> ExecuteAsync(StepContext ctx)
    {
        var ok = await RunLeakDeviceAsync(ctx.CancellationToken);
        return ok
            ? StepResult.Ok(ReviewCode.OK_TestStart)
            : StepResult.Ng(ReviewCode.NG_TestStart, "泄漏量超上限");
    }
}
```

```csharp
var engine = new StationEngine(context, new IStationStep[]
{
    new MyInStationStep(),
    new MyLeakTestStep(),
    new MyTestFinishStep(store),
    new MyOutStationStep(),
});
```

步骤里要卡权限时：

```csharp
if (!context.Station.Session.HasRole(UserRole.工程师))
{
    return StepResult.Ng(ReviewCode.NG_TestStart, "权限不足");
}
```

未启用登录时 `Session` 是匿名管理员，`HasRole` 放行。角色数值：操作员 0 < 工程师 1 < 管理员 2。

## 5. 实时数据页是工站自己的

`MainForm` 构造函数的第三个参数类型是 `Control`。为 null 时抛异常，消息是「实时数据页由工站自己提供」。之后只做两件事：`Dock = Fill`，加到页签 `pageRealtime`（标题「实时数据」）。主界面不假定里面是表格、曲线还是图像。

因此这一页可以是表格、曲线、两者拼在一起、实时图像标注，或几个画面组合。布局由这个控件自己决定。

替换点只有 `Program.cs` 那一行：

```csharp
var realtimeView = new MyStationView();   // 任何 WinForms 控件
Application.Run(new MainForm(context, engine, realtimeView, CreatePlcClient, CreateApiClient));
```

### 5.1 当前钩子（以 main 为准）

| 钩子 | 谁调用 | 说明 |
|---|---|---|
| `MainForm(..., Control realtimeView, ...)` | `Program.cs` | 唯一的页面注入点 |
| `StationContext.Live` | 构造上下文时 `new CycleLiveData()` | 可选数据袋。引擎不读不写 |
| `StepContext.Live` / `PublishItem` / `PublishPoint` / `PublishVerdict` | 步骤自己调用 | 转发到 `CycleLiveData`。页面不用这个袋子就不要调用 |
| `CycleLiveData.Changed` | 每次 `BeginCycle`、记住 SN、发布行/点/结论时 | 注释写明可能在引擎线程上触发。界面自己切回 UI 线程 |
| `CycleLiveData.Snapshot()` | 界面来取 | 只读快照：`SerialNumber`、`Verdict`、`Reason`、`Rows`、`Series` |
| `StationEngine.StepExecuted` | 步骤返回 `StepResult` 之后 | `MainForm` 用来在 NG 时切页。页面也可以订，但别在里面写业务 |
| `StationEngine.ReserveBoolsChanged` | 预留 bool 变化 | 主界面未用 |

`CycleLiveData` 的规则：

- `BeginCycle()` 清空表格、曲线、结论和记住的 SN。新的一件开始时由**工站步骤**调用。引擎不会代劳。示例放在进站开头。
- `PublishItem`：同名项目覆盖，不追加重复行。空名称直接丢掉。
- `PublishPoint`：按曲线名追加点，没有这条曲线就创建。X 的含义由工站定（序号、时间、角度都可以）。
- `PublishVerdict(passed, reason)`：本周期一旦是 `ProductVerdict.Ng`，后面的 OK **不会**盖掉它。相同结论且原因相同则不触发 `Changed`。
- `RememberSerialNumber`：出站把 `State.SerialNumber` 清掉之后，袋子里还可以留着这一件的 SN。

不做实时页的工站可以完全不引用 `CycleLiveData`。图像标注、多画面组合就属于这种。

### 5.2 DemoLiveView 只是能跑起来的例子

`DemoLiveView` 不是契约。它订阅 `context.Live`，用 WinForms `Timer`（200 ms）在 UI 线程上 `Snapshot` 再画。`Changed` 里只把脏标记设上，避免在引擎线程画控件。

布局是三行：大号 OK/NG（字号 40）、表格（项目 / 标准 / 实测值 / 结果）、一条 SunnyUI 曲线。没有行就藏表格，没有曲线就藏图，剩下的区域撑满。曲线轴名写死为「采样」「数值」。

换掉 `Program.cs` 里的 `new DemoLiveView` 之后，这个类可以留在仓库里当参考，也可以不再实例化。不要把它的三行布局当成工站必须遵守的样子。

## 6. 产品 OK/NG 和程序报警不是一回事

| | 产品结论 | 程序报警 |
|---|---|---|
| 含义 | 这一件产品合格还是不良 | 通信、步骤抛异常、落库失败等程序故障 |
| 写入 | 步骤调用 `PublishVerdict`（或页面自己的状态） | `AlarmManager.Set(key, active, message)` |
| 显示 | **只在实时数据页**，画法由该控件决定。示例是大号 OK/NG | 身份条和页签之间的报警条，**不随页签隐藏** |
| 引擎 | 不调用 `PublishVerdict`，也不因为 `StepResult.Ng` 去点亮报警条 | 连接、心跳、读流程字、回写审查码、步骤抛异常时自己 `Set` |

报警条文案：

- 没有活动报警：`无程序报警`（绿字、深底）。
- 有报警：`程序报警　` 加上各条 `键` 或 `键：消息`，按 `RaisedAt` 从新到旧，用 `；` 连接。鼠标悬停与文本相同。

自动切到「实时数据」页（`main` 上的 `MainForm`）只有两种：

1. `AlarmManager.Changed` 且 `Activated == true`（上升沿）。恢复（`Activated == false`）不切页。
2. `StepExecuted` 且 `Result.Success == false`。成功步骤不切页。

所以：产品 NG 若只 `PublishVerdict(false)` 而 `StepResult` 仍是 Ok，**不会**因为结论本身切页；示例步骤在判不良时同时返回 `StepResult.Ng`，因此会切页。落库失败会另起一条程序报警，上升沿同样切页。

## 7. 日志、状态灯、报警、状态

### 7.1 日志：模板已经接到界面

业务里用 `context.Log`（即 `StationContext.Logger`，类型 `IAppLogger`）：`Debug` / `Info` / `Warn` / `Error`。`Log4NetLogger` 既写 log4net，也触发 `Written`。订阅者抛异常会被吃掉，不影响主循环。

`MainForm` 已订阅 `Written`，经 `UiLogSink` 刷到「运行日志」。队列上限 2000 条（超出丢最旧），每 200 ms 批量写入，界面保留 800 行。不用再做第二个日志框。

`log4net.config` 的 root 级别是 `INFO`，文件 `Logs\host.log`，按日期滚动，最多 30 个备份，格式 `%date{HH:mm:ss.fff} [%level] %message`。因此 **Debug 默认不进文件，但仍会进界面**（`Written` 不看 log4net 级别）。`.gitignore` 忽略了 `Logs/`。

`AppConfig.SaveTextLog`、`SaveDbLog` 能在配置页里改，**当前没有任何代码读取它们**。关它们不会停掉 log4net，也不会开始把日志写入 SQLite。

### 7.2 状态灯：模板已经绑定

`RefreshState` 每 300 ms：

| 灯 | 规则 | 颜色 |
|---|---|---|
| PLC | `State.PlcConnected`（引擎在连上/断开时写） | 连通为绿 |
| MES | `api.xml` 的 `Enabled == false` 时为红。开启后才按连通探测点亮，约每 6 秒一次（每 20 次界面刷新，进行中不重入） | 关闭为红；开启且探测通过为绿 |
| 报警 | `Alarms.ActiveCount > 0` | 有报警为红 |
| 运行 | `engine.IsRunning` | 监控中为蓝 |

工站不要自己画这四盏灯。

MES 关闭时灯必须是红色。`HttpApiClient.PingAsync` 在 `Enabled == false` 时直接返回 true，那只表示 `PostAsync` 被放行、不发 HTTP，不能把 MES 灯点绿。后续改动会把灯对齐到「关闭即红」。`Enabled == true` 时，探测是对 `BaseUrl` 发 GET，状态码小于 500 为绿，异常为灭。步骤里不要为了刷灯去改 `PlcConnected`。

### 7.3 AlarmManager：程序报警往这里放

```csharp
context.Alarms.Set("测试数据落库失败", true, ex.Message);   // 上升沿才触发 Changed
context.Alarms.Set("测试数据落库失败", false);              // 下降沿
```

语义与原来的 `Alarmer.Content(key, active)` 相同：状态没变不发事件。同一键再次 `Set(true)` 只会更新 `Message`（若传入非空）。`Clear()` 直接清空字典且**不**发事件；`StartAsync` 会 `Clear()`，报警条靠 300 ms 刷新回到「无程序报警」。

引擎已经占用的键（工站别复用这些字符串，除非就是要接同一条报警）：

`PLC未配置`、`PLC轮询异常`、`连接PLC失败`、`写心跳失败`、`读取流程字失败`、`读取预留位失败`、`回写审查结果失败`、`步骤异常:{步骤名}`。

`StepContext.WritePlcWord` 失败时使用 `写入失败:{地址键}`。

产品不良不要塞进 `AlarmManager`，否则报警条会把它显示成程序故障，并在上升沿切页。产品不良用 `PublishVerdict` 加 `StepResult.Ng`。

`AlarmRecord` / `TestDataStore.SaveAlarmAsync` 可以把报警写入 SQLite 的 `Alarm` 表。引擎和示例步骤都**没有**自动调用它。要落库就在自己的订阅或步骤里写。

### 7.4 StationState：引擎写，界面读

| 字段 | 谁在写 | 界面是否使用 |
|---|---|---|
| `RunStatus` | 引擎 `RaiseStatus`。枚举有 None、初始化中、初始化完成、正在监控、正在停止、监控已停止、系统异常。引擎实际会写的是：启动时「初始化中」，循环正常时「正在监控」，缺 `PLC_指令` 或主循环抛异常时「系统异常」，停止过程「正在停止」「监控已停止」。`初始化完成` 只有枚举，没有赋值 | 不直接绑控件。非空消息会打成 `[状态]` 日志 |
| `PlcConnected` | 引擎 | PLC 灯 |
| `ApiConnected` | `MainForm.CheckApiAsync` 写入当次 `PingAsync` 结果 | MES 灯不按「Ping 为 true 就点绿」。`Enabled == false` 时灯为红，见第 7.2 节 |
| `ProcessWord` / `ProcessContent` | 引擎每轮 | 身份条 |
| `PreviousProcessWord` | **没有任何代码赋值**。边沿用的是引擎私有的 `_handledWord` | 否 |
| `SerialNumber` / `TrayNo` | 示例进站写入 SN。复位按钮清空这两项。`TrayNo` 由工站在需要显示托盘时自行维护；`PLC_托盘号` 只是地址配置，见第 8.2 节 | 身份条 |
| `ReviewCode` | 引擎回写前，以及 `StepContext.WriteReview` | 否 |
| `RunningStep` | 分发期间为步骤名，结束置空 | 身份条 |
| `StartTime` / `EndTime` / `Testing` | 示例步骤 | 主界面不显示 |
| `CycleCount` / `NgCount` | 良品 / 不良，按件记录（一个产品周期、一个 SN 一次）。实现对齐见第 6 节 | 身份条 |

字段是普通属性，界面读到的是近似快照。需要同一时刻的副本时用 `State.Snapshot()`（浅拷贝）。

## 8. 配置

三份 XML 由 `ConfigManager` 从 `<程序目录>/config/` 加载。文件缺失或损坏时用默认值重写，并在返回消息里说明，**启动不失败**。`Program.cs` 把这条消息记成 Warn。

| 文件 | 类型 | 工站通常改什么 |
|---|---|---|
| `app.xml` | `AppConfig` | 工站号 `EquId`、名称、产线 `Line`、站位、段名、轮询、心跳拍数、`RequiredSteps`、`SnLength`、`Simulate`、`SimulateStepSeconds`、是否启用登录 |
| `plc.xml` | `PlcConfig` | 协议、IP、端口、CPU、机架、插槽、站号、超时、重连间隔、地址表 |
| `api.xml` | `ApiConfig` | `BaseUrl`、超时、重试、`Enabled`、请求头、端点表 |

另外两份不是这三件套，但确实存在：

- `log4net.config`：跟程序走，改级别和路径可以。不要删，否则没有文件 appender（`InitLogger` 在文件不存在时仍会创建 logger，只是没有这份配置）。
- `config/users.xml`：只有 `EnableLogin` 为 true 时由 `AuthService` 读写。首次生成 `admin / admin123`，并标记必须改密。

`XmlConfigStore.Save` 用临时文件再替换，并留备份。配置页打开时 `Clone` 出副本，取消不影响内存里的原对象。保存校验和「保存即热加载」见 README 第 7 节。热加载路径是 `MainForm.ApplyConfigAsync`。

### 8.1 app.xml 里安全和不安全的改法

可以改、并且有代码在读：

- `[PC]`：`PcNo`、`EquId`、`WorkStationName`、`Line`、`Station`（首站 / 普通工站 / 尾站）、`Section`。名称和产线显示在顶栏；`EquId`、`Line`、`Section` 会被示例落库抄进记录。`PcNo`、`Station` 没有参与流程判断，只是配置和副标题（副标题会带站位枚举）。
- `[运行]`：`PollIntervalMs`（引擎至少 10 ms）、`HeartbeatTicks`（至少 1）、`RequiredSteps`。
- `[条码]`：`SnLength`。0 表示示例进站不校验长度。
- `[调试]`：`Simulate`、`SimulateStepSeconds`。命令行 `--simulate` 会在加载后覆盖内存，不写回文件。
- `[权限]`：`EnableLogin`。`SessionTimeoutMinutes` **没有被读取**，配了也不会自动锁屏。
- `[存储]`：`DatabasePath` 默认 `Data\host.db`，相对路径拼在程序目录下，绝对路径则原样使用。`SaveTextLog`、`SaveDbLog` 没有被读取。

`main` 上没有「界面主题」字段。那是 PR #2 的 `AppConfig.Theme`。

### 8.2 plc.xml

默认连接：`SiemensS7`，`192.168.0.1:102`，CPU `S1200`，机架 0，插槽 0。重连间隔默认 2000 ms。

地址表把键名映射到 PLC 地址。现场要换点位时只改地址，不改代码，也不必让每一项都自动出现在 `StationState` 上。

默认地址表（`ConfigManager.CreateDefaultPlc`）：

| 键（`AddressKeys`） | 方向 | 地址 | 长度 | 类型 | 说明 |
|---|---|---|---|---|---|
| `MES_心跳` | RW | M100.0 | 0 | Bool | 引擎按这个键翻转心跳 |
| `PLC_指令` | R | MW200 | 2 | Word | 引擎读流程字；复位按钮会写 0。缺了无法启动监控 |
| `PLC_预留bool` | R | M110.0 | 16 | Bool | 引擎按这个键读取，变更事件留给工站 |
| `MES_审查结果` | RW | MW210 | 0 | Word | 引擎按这个键回写审查码 |
| `MES_SN` | W | DB1.DBB0 | 20 | String | 示例进站在仿真补 SN 时写入 |
| `PLC_SN` | R | DB1.DBB100 | 20 | String | 示例进站按这个键读取 |
| `PLC_托盘号` | R | MW220 | 0 | Word | 可替换的读地址 |

键名可以加。引擎固定使用前四个键名，改的是它们的绝对地址。不要改这四个键的**名字**，除非同时改 `AddressKeys` 和所有引用。`PLC_托盘号` 留在表里，是为了现场更换托盘地址时只改配置。`Remark` 程序不读。重名键保留第一个，并在加载时 Warn。

地址写法随协议变，见 README 第 7.1 节。配置页的型号列表来自 `PlcDeviceCatalog`，不要在页面里再写一套。

### 8.3 api.xml

`HttpApiClient` 按端点 **Key** 拼 `BaseUrl + Path`。默认端点：

| Key | Path |
|---|---|
| `ApplySn` | `/api/ProcessStation/RequestSnNumber` |
| `PassStation` | `/api/ProcessStation/PassStation` |
| `UploadTestData` | `/api/TestData/UpLoad` |
| `RegisterNg` | `/api/BadProduct/Register` |

默认请求头 `appId=template`、`appKey=change-me`。`Enabled == false` 时 `PostAsync` 不发 HTTP，直接返回成功，Body 为 `{"Success":true,"Mesg":"接口已关闭"}`。这只放行业务调用。顶栏 MES 灯在关闭时仍应为红色，见第 7.2 节。未配置的 Key 返回失败，消息是 `api.xml 未配置端点：{key}`。

示例步骤没有调用这些端点。接入时：

```csharp
var response = await context.Api.PostAsync(
    "ApplySn",
    new { LineCode = context.App.Line },
    context.CancellationToken);
```

载荷用 `System.Text.Json` 序列化，`PropertyNamingPolicy` 为 null，属性名按 CLR 原样。

## 9. 数据

本地库路径见 `StationContext.DatabasePath`。`Program.cs` 在建引擎之前 `EnsureCreated()`：目录不存在会创建，表已在则不动。失败只记「初始化本地数据库失败，测试数据将不会落库」，程序继续跑。

`HostDbContext` 三张表，没有迁移：

| 表 | 实体 | 关系 |
|---|---|---|
| `TestData` | `TestDataRecord` | 一件产品一条 |
| `TestDataItem` | `TestDataItemRecord` | 外键 `RecordId`，级联删除 |

## 10. 日间 / 夜间主题（PR #2，尚未进入 main）

本节描述 [PR #2](https://github.com/gouhongfei258/hosttemplate/pull/2) 的代码（头提交 `c550b52`，分支 `cursor/day-night-theme-4667`）。`main`（`5c277f6`）上没有 `MainTheme`、`IMainThemeAware`、`UiThemeMode`，也没有顶栏主题按钮。`DemoLiveView` 在 `main` 上是写死的深色。合并之前，按本节做会编译失败。

合并之后的行为如下。

### 10.1 按钮与持久化

- 按钮 `btnTheme` 在顶栏，状态灯的左边。设计器位置 `(606, 32)`，大小 `128×36`，锚在右上；四盏灯从 x = 750 起。
- 夜间模式下按钮文字是 **日间**，提示「当前是夜间界面，点击切换为日间」。日间模式下文字是 **夜间**，提示相反。文字来自 `MainTheme.ThemeButtonText`，不是固定标题。
- 点击时把 `AppConfig.Theme` 在 `UiThemeMode.夜间` 与 `UiThemeMode.日间` 之间翻转，立刻 `ApplyTheme`，再 `Config.SaveApp`。保存失败只打 Warn「保存界面主题失败：…」，内存里的颜色已经换了，下次启动仍以 XML 为准。
- 字段：`[界面] / 01.界面主题`，枚举 `夜间 = 0`、`日间 = 1`，默认 `夜间`。配置页的 PropertyGrid 会列出它。旧的 `app.xml` 没有这个元素时，XmlSerializer 保留属性初值，仍是夜间。
- 启动时 `ApplyTheme(MainTheme.For(_context.App.Theme))`。`For` 仅在 `日间` 时返回 `MainTheme.Day`，其余返回 `MainTheme.Night`。

### 10.2 换色范围

`ApplyTheme` 覆盖：窗口底、顶栏、身份条、底栏、工站名/副标题/流程字/SN/托盘/轨迹/计数/底栏提示/版本号的前景色、四盏状态灯的文字色和灭灯色、两个页签页底色、日志框、SunnyUI 页签、开始/停止/复位/配置/账号/主题按钮、日志级别色（并重画已有日志行）、报警条（空闲色或活动色）。

SunnyUI 先套 `UIStyle.Black`（夜间）或 `UIStyle.Blue`（日间），再打开 `StyleCustomMode` 写回模板自己的颜色。夜间因此仍是原来的石板深色，不是 SunnyUI 的纯黑。

### 10.3 IMainThemeAware

```csharp
namespace HostTemplate.App.Controls
{
    public interface IMainThemeAware
    {
        void ApplyMainTheme(MainTheme theme);
    }
}
```

`MainForm` 只遍历 `pageRealtime.Controls` 的**直接子控件**。注入的那一个控件如果实现了接口，就调用 `ApplyMainTheme`。嵌套在内部的子控件不会被自动发现；包了一层外壳时，外壳要实现接口并自己往下传。

没有实现该接口的实时页保持自己原来的颜色。页签页的 `BackColor` 会变，但控件 `Dock = Fill` 时操作员看不到页签底色。

PR 里的 `DemoLiveView` 已实现该接口，并使用 `MainTheme` 上的页面底、表格、曲线样式（`ChartStyle`：夜间 `Dark`，日间 `Plain`）、结论区 OK/NG/等待色、合格/不良字色。可用的颜色都是 `MainTheme` 的公共属性（`PageBack`、`GridText`、`VerdictOkBack`、`PassFore`、`FailFore` 等），定义在 `src/HostTemplate.App/Controls/MainTheme.cs`。

自定义页要跟主题时：

```csharp
public sealed class MyStationView : UserControl, IMainThemeAware
{
    public void ApplyMainTheme(MainTheme theme)
    {
        BackColor = theme.PageBack;
        // 结论区、表格、图像上的字用 theme 里的颜色重画
    }
}
```

## 11. 本地构建、测试、版本、CI

本地版本钉在 `Directory.Build.props`：

- `VersionMajor = 1`，`VersionMinor = 0`，`VersionPatch` 默认 `0`。
- `Version` = `1.0.0`。`AssemblyVersion` 和 `FileVersion` = `1.0.0.0`。
- 不把 CI 的补丁号提交回仓库。

在 git 工作副本里编译时，SDK 还会把提交号附在信息版本上（`1.0.0+...`）。窗口标题和右下角显示的是 `MainForm.ReadDisplayVersion()`：优先 `AssemblyInformationalVersion`，有 `+` 时提交号最多保留 7 位；没有信息版本时退回程序集版本的三段。

本地：

```bash
dotnet test HostTemplate.sln
dotnet build src/HostTemplate.App/HostTemplate.App.csproj -c Release
```

App 是 `net8.0-windows`。测试项目是 `net8.0`，不打开主窗口。

CI 只有 `.github/workflows/release.yml`。触发条件是 **push 到 `main`**（合并 PR 的常规结果），运行器 `windows-latest`，权限 `contents: write`。

1. `actions/checkout@v4`，`actions/setup-dotnet@v4`，SDK `8.0.x`。
2. `dotnet test HostTemplate.sln -c Release`，并传入  
   `-p:VersionPatch=$GITHUB_RUN_NUMBER`、`-p:SourceRevisionId=`（`GITHUB_SHA` 前 7 位）。
3. `dotnet publish src/HostTemplate.App/HostTemplate.App.csproj -c Release` 到 **`$RUNNER_TEMP/HostTemplate-1.0.<run_number>`**。同样的两个属性。
4. 检查存在 `HostTemplate.exe`，且 `FileVersion` 等于 `1.0.<run_number>.0`。
5. 在 `HostTemplate.dll` 的字节里查找信息版本字符串 `1.0.<run_number>+<7位SHA>`，找不到则失败。
6. 把发布目录打成 `$RUNNER_TEMP/HostTemplate-1.0.<run_number>.zip`。
7. 标签 **`v1.0.<run_number>`**（不加 `+SHA`）。Release 标题 `HostTemplate 1.0.<run_number>`。说明里写版本、文件版本、`InformationalVersion` 和短提交号。标签已存在则 `gh release upload --clobber` 并更新说明，否则 `gh release create`，`--target` 为 `GITHUB_SHA`。

发布产物只挂在 GitHub Release 上。不要在仓库里建 `release/` 或 `publish/`，不要提交 exe、dll、zip。`.gitignore` 已忽略 `bin/`、`obj/`、`Logs/`、仓库根的 `/release/`、`/publish/`、`/Data/`（这是运行库目录；`src/HostTemplate.Core/Data/` 源码要入库）。

## 12. 做与不做

**做**

- 新业务写成 `IStationStep`，在 `Program.cs` 注册。一个流程字一个类。
- 实时画面做成一个 `Control`，在 `Program.cs` 传给 `MainForm`。表格、曲线、图像标注、多画面组合都放在这个控件里。
- 产品 OK/NG 画在实时页上。身份条良品/不良按件记，一个 SN、一个产品周期一次。程序故障用 `Alarms.Set`，沿用上升沿/下降沿。
- MES 关闭（`api.xml` 的 `Enabled == false`）时，顶栏 MES 灯为红色。
- 点位走 `AddressKeys` + `plc.xml`。换 IP、换地址后靠配置页保存热加载，不要让现场改完必须重编译。
- 测试记录在步骤里调用 `TestDataStore.SaveAsync`。落库失败报警，不要卡死节拍。
- 需要主题跟随的自定义实时页，在 PR #2 合并后实现 `IMainThemeAware`，并实现在交给 `MainForm` 的那一层控件上。
- 本地构建接受 `1.0.0`。发布版本只存在于 GitHub Release。

**不做**

- 不把业务流程、PLC 读写、合格判定写进 `MainForm`。
- 不把 `DemoLiveView` 的「大号结论 + 表格 + 曲线」当成页面契约，也不假设每个工站都要引用 `CycleLiveData`。
- 不在引擎里填实时页面，也不要让引擎拥有产品结论。
- 不用静态 Global 在步骤和界面之间传 SN、结论或客户端。
- 不把产品不良登记成 `AlarmManager` 的键，除非确实希望它出现在始终可见的程序报警条上。
- 不把良品/不良按步骤成功次数累加。一件产品只记一次。
- 不把地址表理解成「每一项都会自动写入 `StationState`」。`PLC_托盘号` 只是可替换的 PLC 地址。
- 不在 `Enabled == false` 时把 MES 灯当成连通。`PingAsync` 返回 true 只表示调用被跳过，灯应为红色。
- 不依赖 `SaveTextLog`、`SaveDbLog`、`SnPrefix`、`SessionTimeoutMinutes`、`PreviousProcessWord` 已经生效。它们在 `main` 上没有运行时行为。
- 不在 `main` 上编写 `IMainThemeAware` 或读写 `AppConfig.Theme`。等 PR #2 合并。
- 不把 `release/`、`publish/` 或编译输出提交进仓库。
- 不把 net48 的 `HslCommunication.dll` 引回来。用 NuGet 12.8.3。
