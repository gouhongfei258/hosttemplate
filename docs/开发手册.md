## 2. 界面与引擎

`MainForm` 只做展示，并把按钮交给已经装配好的对象。业务在 `StationEngine` 和 `IStationStep`。

主窗口自上而下：

| 区域 | 内容 |
|---|---|
| 顶栏 | 产品标志、工站名、产线 / 工站号 / 站位、四盏状态灯、日间夜间按钮 |
| 身份条 | 流程字（Consolas 40 磅）、流程名、SN、托盘、轨迹、良品 / 不良 |
| 报警条 | 程序报警。没有报警时显示「无程序报警」 |
| 页签 | 「实时数据」「运行日志」 |
| 底栏 | 开始监控、停止监控、复位流程、系统配置、账号管理、获取远端配置、程序更新、软键盘、提示和版本 |

界面字体是 Microsoft YaHei UI：工站名 22 磅粗体，流程名 18 磅，产线行和底栏提示 14 磅，报警条 11 磅粗体，底栏按钮 11 磅，软键盘 12 磅粗体，主题按钮 14 磅粗体。流程字是 Consolas 40 磅粗体，右下角版本是 Consolas 14 磅，运行日志是 Consolas 10 磅。示例实时页的结论字是 Microsoft YaHei UI 40 磅粗体。这些字体写在窗体上，配置里没有字体项。

`StationEngine` 的循环只做这些事：

- 按 `PollIntervalMs` 轮询。未连接时按 `ReconnectDelayMs` 调用 `OpenAsync`。客户端自己不会在一次读写失败后偷偷重连。
- 每 `HeartbeatTicks` 次轮询翻转 `MES_心跳`。
- 读 `PLC_指令` 的两个 Word，用第一个作为流程字。和上次已处理的值不同才分发。
- 同一时刻只跑一个步骤。上一步还没结束时本轮直接返回，下一轮再试，流程字不会被丢掉。
- 步骤返回 `StepResult` 后，引擎回写审查码、追加轨迹，并按下面的规则给这一件记良品或不良。
- 通信失败时置报警。写心跳失败或读流程字失败时 `CloseAsync`，下一轮再连。读预留位失败、回写审查码失败只报警，不断开连接。
- 引擎不填写实时页面。地址表只提供 PLC 点位，`StationState` 由引擎和步骤写入。

地址键在 `AddressKeys`。换点位只改 `plc.xml`。详见 [配置](配置.md)。

### 流程字和审查码

`ProcessWords`：

| 常量 | 值 | 显示 |
|---|---|---|
| `Idle` | 0 | 等待进站 |
| `InStation` | 10 | 进站 |
| `TestStart` | 20 | 测试开始 |
| `TestFinish` | 30 | 测试结束 |
| `OutStation` | 40 | 出站 |
| `ReTest` | 50 | 复测 |

未列出的值显示为「未定义流程(n)」。没有对应步骤时记一次警告并跳过。

`ReviewCode`：

| 名称 | 值 |
|---|---|
| `OK_InStation` / `NG_InStation` | 1 / 2 |
| `OK_TestStart` / `NG_TestStart` | 3 / 4 |
| `OK_TestFinish` / `NG_TestFinish` | 5 / 6 |
| `OK_OutStation` / `NG_OutStation` | 7 / 8 |
| `IsSample` | 9 |
| `NG_PowerReTest` | 10 |
| `OK_Done` | 20 |
| `NG_Product` | 30 |

步骤用 `StepResult.Ok` 或 `StepResult.Ng` 返回。引擎把审查码写进 `StationState.ReviewCode`，地址表里有 `MES_审查结果` 时再写到 PLC。

### 一件只记一次

`StationState.CycleCount` 是良品件数，`NgCount` 是不良件数。一件产品只加其中一个，不按步骤累加。

| 时机 | 审查码 | 计数 |
|---|---|---|
| 步骤结束，这件还没收口 | `NG_InStation`、`NG_TestStart`、`NG_TestFinish`、`NG_OutStation`、`NG_PowerReTest`、`NG_Product` | 不良 +1 |
| 步骤结束，这件还没收口 | `OK_OutStation`、`OK_Done` | 良品 +1 |
| 步骤结束，这件还没收口 | `OK_InStation`、`OK_TestStart`、`OK_TestFinish`、`IsSample` | 不加 |
| 流程字回到 0，或下一件进入进站 | 状态里最后一枚审查码属于上面的 NG | 若还没记过，不良 +1 |
| 流程字回到 0，或下一件进入进站 | 最后一枚属于上面的 OK | 若还没记过，良品 +1 |

已经记过的这一件，后面的审查码不加件数。先记成不良之后，同一件后面的 OK 不加良品。进站步骤开始前，会用上一件的最后一枚审查码把还没记过的件数收口。

### 报警

`AlarmManager.Set(key, active, message)` 只在该键从关到开、或从开到关时触发 `Changed`。主界面订阅后刷新报警条；报警升起时切到「实时数据」。步骤返回失败时也会切到这一页。

引擎使用的键包括：`PLC未配置`、`连接PLC失败`、`写心跳失败`、`读取流程字失败`、`读取预留位失败`、`回写审查结果失败`、`PLC轮询异常`、`步骤异常:{步骤名}`。`StepContext.WritePlcWordAsync` 失败时使用 `写入失败:{键名}`。

### 轨迹和落库

`ProcessTrace` 记录本件走过的流程字，末尾相同的值不重复追加。`Text` 形如 `10-20-30-40`。`Check` 用来核对 `AppConfig.RequiredSteps`，默认是 10、20、30。

测试记录用 `TestDataStore` 写入 SQLite。相对路径相对配置目录。`SaveAsync` 保存 `TestDataRecord` 和测试项，`SaveAlarmAsync` 保存报警，`QueryRecentAsync` 按新到旧取最近若干条。主界面没有历史查询页。示例工站在测试结束步骤里落库；落库失败只报警，不中断步骤。

## 3. 写一个工站步骤

一个流程字对应一个 `IStationStep`：`Word`、`Name`、`ExecuteAsync`。同一流程字注册两次会在构造引擎时抛异常。

```csharp
using HostTemplate.Core.Flow.Engine;
using HostTemplate.Core.Flow.Process;

public sealed class MyLeakTestStep : IStationStep
{
    public ushort Word => ProcessWords.TestStart;
    public string Name => "气密性检测";

    public async Task<StepResult> ExecuteAsync(StepContext ctx)
    {
        var ok = await RunLeakDeviceAsync(ctx.CancellationToken);
        return ok
            ? StepResult.Ok(ReviewCode.OK_TestStart)
            : StepResult.Ng(ReviewCode.NG_TestStart, "泄漏量超上限");
    }
}
```

在 `Program.RunWithConfig` 里把步骤交给引擎。模板现在是：

```csharp
var engine = new StationEngine(context, DemoSteps.Create(store));
```

`DemoSteps` 注册了进站、测试开始、测试结束、出站四步，放在 `src/HostTemplate.App/Steps/DemoSteps.cs`。换工站时改这个列表，或换成自己的工厂方法。

`StepContext` 上常用的成员：

| 成员 | 作用 |
|---|---|
| `Plc` / `Api` / `Log` / `Alarms` / `State` / `Trace` / `App` | 本工站的客户端、日志、报警、状态、轨迹、配置 |
| `ReadPlcStringAsync(key, length)` | 按地址键读字符串，失败得到空串 |
| `WritePlcWordAsync(key, value)` | 按地址键写 Word，失败时置报警 |
| `WriteReviewAsync(code)` | 步骤中途回写审查码。步骤结束时引擎还会再写一次 |
| `PublishItem` / `PublishPoint` / `PublishVerdict` | 写入可选的 `CycleLiveData`。页面不用这个数据袋时可以不调用 |
| `CancellationToken` | 停止监控时取消步骤 |

示例进站步在仿真且 PLC 里没有 SN 时，按 `SnLength` 造一条条码。`SnLength` 大于 0 且长度不符时返回 `NG_InStation`。`SnPrefix` 会保存在 `app.xml` 里，示例步骤不读取它。

接 MES 时按端点键调用，不写死 URL：

```csharp
var response = await ctx.Api.PostAsync(
    "ApplySn",
    new { LineCode = ctx.App.Line },
    ctx.CancellationToken);
```

`api.xml` 里「启用接口调用」为 false 时，`PostAsync` 直接返回成功，正文是 `{"Success":true,"Mesg":"接口已关闭"}`。灯的颜色见下一节。

## 4. 按测试类型加载实时页

`app.xml` 的 `TestType`（配置页显示名「测试类型」）决定「实时数据」放哪个控件。登记表在 `HostTemplate.App.Startup.LiveViewCatalog`，选择规则在 `LiveViewRegistry<TContext, TView>`。

| `TestType` | 页面 |
|---|---|
| 空白、`默认`、`default`（忽略大小写） | 内置 `DemoLiveView` |
| 已用 `Register` 登记的名字 | 登记时的工厂方法 |
| 其他未登记的名字 | 内置 `DemoLiveView` |

`默认` 和 `default` 不能登记成自定义页，`Register` 会抛异常。自定义类型在 `LiveViewCatalog.Create` 之前登记，`Program.RunWithConfig` 里有示例位置：

```csharp
LiveViewCatalog.Register("扭矩", ctx => new TorqueLiveView(ctx));
var realtimeView = LiveViewCatalog.Create(context);
```

`Create` 把 `StationContext` 交给工厂。页面可以是任意 `Control`。保存配置并热加载后，`MainForm` 会再调用同一个工厂，测试类型改了就会换页。

`DemoLiveView` 只是示例：大号结论、测试项表格、一条曲线。它读 `CycleLiveData`，并实现 `IMainThemeAware`。图像标注或其他布局不必使用 `CycleLiveData`。数据袋由工站自己写；新的一件开始时调用 `BeginCycle()`。本周期一旦 `PublishVerdict(false, …)`，后面的 OK 不会盖掉这条结论。`Changed` 可能在引擎线程上触发，界面要切回 UI 线程。示例页用 200 ms 定时器刷新。

`CycleLiveData` 的行是项目、标准、实测、合格，同名项目覆盖。曲线按系列名追加点，X 由工站自己定义。

## 5. MES 灯

`HttpApiClient.IsAvailable` 等于 `api.xml` 的 `Enabled`。`PingAsync` 在接口关闭时返回 false；接口打开时对基地址发 GET，状态码小于 500 视为连通。

`MesLampState.Resolve` 的结果：

| 条件 | 灯 |
|---|---|
| 没有 API 客户端 | 灭 |
| 有客户端且接口关闭 | 红色（与报警灯同色）。与探测结果无关 |
| 接口打开且探测成功 | 绿色 |
| 接口打开且探测失败 | 灭 |

主界面每 300 ms 刷新一次。接口打开时每 20 次刷新探测一次。从关闭重新打开、灯还是红色时，会立刻再探测一次。

## 6. 主题、标志、图标、软键盘

`AppConfig.Theme` 为 `夜间` 或 `日间`，默认夜间。顶栏按钮立即切换并 `SaveApp`。夜间界面按钮文字是「日间」，日间界面按钮文字是「夜间」。配色在 `MainTheme`。夜间以 SunnyUI 的 `UIStyle.Black` 为底再盖上模板自己的深色；日间以 `UIStyle.Blue` 为底再盖上浅色。自定义实时页实现 `IMainThemeAware.ApplyMainTheme` 就会一起换色，不实现则保持自己的颜色。

产品标志是嵌入资源 `HostTemplate.App.Assets.logo-byd-shisibu.png`，可访问名称「十四事业部装备中心数采系统」。日间和夜间都放在白底上。资源打不开时，标志区域隐藏，程序继续启动。

窗口图标来自输出目录的 `HostTemplate.ico`（工程里是 `Assets/HostTemplate.ico`，同时是 `ApplicationIcon`）。打不开文件时继续用 exe 里嵌的图标。快捷方式也优先用这个 ico。

底栏「软键盘」调用 `OnScreenKeyboard`。`Environment.SystemDirectory` 下有 `osk.exe` 就启动它；否则启动 `%CommonProgramFiles%\microsoft shared\ink\TabTip.exe`；两个路径都不存在时按名字启动 `osk.exe`。失败时写日志并弹出「打不开屏幕键盘」。

## 7. 开机自启和快捷方式

`app.xml` 的 `StartWithWindows` 默认 false。为 true 时写入当前用户启动项：

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `HostTemplate`，数据是带引号的程序路径。不需要管理员权限。关闭开关时删掉这个值。启动时按配置同步一次，在配置页保存时再同步一次。写失败只记日志。

路径按 Velopack 的安装状态选择：

- 已安装、非便携、并且能读到安装版本时，优先 `{安装根}\current\HostTemplate.exe`。这个路径在更新后保持不变。该文件不存在时用正在运行的程序。
- 调试运行或解压运行时，用正在运行的程序。

启动时 `WindowsTaskbarShortcut.Apply` 保证两处快捷方式指向同一路径：

| 位置 | 目录 |
|---|---|
| 任务栏快捷方式文件 | `%AppData%\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar` |
| 开始菜单 | 「程序」文件夹；取不到时用 `%AppData%\Microsoft\Windows\Start Menu\Programs` |

文件名 `HostTemplate.lnk`，说明文字「十四事业部装备中心数采系统」，工作目录是程序所在目录。已经有指向当前程序的任务栏快捷方式时，这次不重写，也不请求钉住。否则若目录里已有目标 exe 文件名相同的快捷方式，或已有 `HostTemplate.lnk`，就改写那一个，并且不请求钉住。目录里都没有时，新建 `HostTemplate.lnk`，窗口显示后再调用 `TaskbarPin.TryPin`。开始菜单使用同一套「已指向当前程序则跳过，否则写入」的规则，不请求钉住。

钉住规则：

- Windows 内部版本低于 26100 时，先调用 `IPinnedList3.Modify`。
- Windows 11 24H2 的内部版本是 26100。内部版本大于等于 26100 时，程序不调用该接口。在这些版本上，接口会返回成功，任务栏上却不出现图标。
- 上面没有钉住时，再看快捷方式菜单里有没有 `taskbarpin`、「Pin to taskbar」、「锁定到任务栏」或「固定到任务栏」。有则执行，没有则到此为止。
- 钉不住只写日志，程序继续启动。日志使用 `WindowsTaskbarShortcut.PinLimitation`，说明快捷方式已经写好，当前 Windows 不接受程序自己静默钉住任务栏，开始菜单里的 HostTemplate 可以右键钉一次。

## 8. 登录

`EnableLogin` 默认 false。关闭时 `StationContext.Session` 是匿名管理员，`HasRole` 全部放行，主界面不显示用户名。

打开后启动时弹出 `LoginForm`。账号在配置目录的 `users.xml`。密码用 PBKDF2-SHA256，10 万次迭代，16 字节盐，32 字节派生值，比对使用 `CryptographicOperations.FixedTimeEquals`。文件缺失或没有账号时生成 `admin` / `admin123`，显示名「超级管理员」，并标记 `MustChangePassword`。登录成功后若该标记为真，弹出「首次登录 · 请修改密码」；「稍后再说」会进入主界面，标记保持为真。新密码至少 6 位，且不能和当前密码相同。改密成功后标记清掉。

角色是 `操作员 < 工程师 < 管理员`，`Session.HasRole(UserRole.工程师)` 按大于等于判断。最后一个启用的管理员不能被停用、降级或删除。启用登录后，只有管理员能打开「账号管理」。

`SessionTimeoutMinutes`、`SaveTextLog`、`SaveDbLog`、`PcNo`、`SnPrefix` 会出现在配置页的属性网格里并写入 `app.xml`。当前主程序不读取这些值。`Section`（段名）只被示例测试结束步骤写入数据库记录的 `TestType` 字段，和界面用的测试类型 `AppConfig.TestType` 不是同一个字段。

## 9. 本地构建、测试和运行

在仓库根目录：

```bash
dotnet test HostTemplate.sln

dotnet run --project src/HostTemplate.App -- --simulate --autostart

dotnet run --project src/HostTemplate.App -- --config

dotnet run --project src/HostTemplate.Backend --urls http://0.0.0.0:5080
```

`HostTemplate.Backend` 的启动配置 `Properties/launchSettings.json` 已把地址设为 `http://0.0.0.0:5080`。不写 `--urls` 时 `dotnet run` 使用这份配置。

| 参数 | 作用 |
|---|---|
| `--simulate` | 强制 `Simulate = true`。`SimulateStepSeconds` 小于等于 0 时设为 3。仿真 PLC 按这个间隔循环推进 10、20、30、40、0 |
| `--autostart` | 主窗口显示后自动开始监控 |
| `--config` | 只打开配置页，关闭后退出，不进主界面 |

接真实 PLC 时把「启用仿真模式」关掉，在「系统配置 → PLC 连接」里选型号并做连接测试。创建客户端失败时，`Program` 会记错误日志并退回 `Siemens7Client`，使用配置里的 IP、端口、CPU、超时、机架和插槽。

本地 `dotnet build` 不传 `VersionPatch` 时版本是 `1.0.0`。带提交号的显示格式见 [更新与打包](更新与打包.md)。

主程序是 Windows x64 的 WinForms 程序。`HostTemplate.App.csproj` 打开了 `EnableWindowsTargeting`，便于在装有 .NET 8 SDK 的环境里编译该项目。界面在 Windows 上运行。

从这份模板改工站名时，在仓库根执行：

```powershell
.\init.ps1 -Name "MyStation" -Title "某产线某工站"
```

脚本把文本里的 `HostTemplate` 换成新名字，并重命名解决方案、项目和目录。执行前关闭 Visual Studio。完成后打开新的解决方案，把 `Steps/DemoSteps.cs` 换成现场步骤。
