# 配置

引导文件、工站配置的加载顺序，以及主界面里的配置页。解决方案和工站步骤见 [开发手册](开发手册.md)。

## 1. 两个目录

程序目录会被版本替换。工站自己的配置和日志放在引导文件指向的目录里。

程序旁边只有引导文件 `bootstrap.xml`。没有这个文件时，若 `%ProgramData%\HostTemplate\bootstrap.xml` 存在，就从那里拷回；否则按代码默认值新建，并写回程序目录。每次读成功后，都会把程序目录里的文件镜像到 `%ProgramData%\HostTemplate\bootstrap.xml`。镜像失败不阻止启动。

随程序发布的 `bootstrap.default.xml` 是样例。加载逻辑不读取它。打包时默认排除程序目录根上的 `bootstrap.xml`，避免把现场填好的引导文件打进安装包。

`BootstrapConfig` 的字段：

| 字段 | 作用 |
|---|---|
| `ConfigDirectory` | 工站配置目录。空则使用 `%ProgramData%\HostTemplate\config`。相对路径按进程当前目录展开成绝对路径 |
| `ServiceBaseUrl` | 本线服务，例如 `http://10.0.0.8:5080`。空则启动时不访问服务。末尾斜杠会被去掉 |
| `StationId` | 向服务要配置和版本时的工站编号。空则使用 `app.xml` 的工站号。启动时如果本地配置还不存在，只能使用这里的编号，默认生成的是 `OP010` |
| `ServiceToken` | 非空时，主机把它放进请求头 `X-Host-Token` |
| `LogDirectory` | 日志目录。空则使用 `%ProgramData%\HostTemplate\Logs`。相对路径按进程当前目录展开成绝对路径 |

`log4net.config` 跟程序走，里面的文件项是相对路径 `Logs\host.log`，按日期滚动，`staticLogFileName` 为 false。启动后 `LogDirectoryConfigurator` 把滚动文件的目录改成 `LogDirectory`，文件名以 `host.log` 开头。改目录失败时，继续使用配置文件里的相对路径。

稳定根目录来自 `Environment.SpecialFolder.CommonApplicationData` 下的 `HostTemplate`。这个特殊目录为空时用临时目录。

## 2. 加载顺序

`StationConfigLoader.ResolveAsync` 的顺序：

1. 配置目录里 `app.xml`、`plc.xml`、`api.xml` 都存在且长度大于 0，就直接加载。这次启动不向服务要配置。
2. 缺目录或缺其中任一文件时，若 `ServiceBaseUrl` 和 `StationId` 都有值，则 `GET /api/stations/{id}/config`，把包写到本地再加载。
3. 没有服务地址、没有工站编号、服务返回的包不完整，或请求失败时，用程序目录 `templates\` 里的同名文件补上缺失项。模板里也没有时，用 `ConfigManager.CreateDefaultApp` / `CreateDefaultPlc` / `CreateDefaultApi`。这次若引导文件里有工站编号，会把新建的 `app.xml` 工站号写成该编号。

补模板时只写缺失或空文件，不覆盖已经存在的配置。`users.xml` 不是启动必需文件。启用登录且账号文件缺失时，`AuthService` 再生成它。

某个必需文件存在但 XML 读失败时，`ConfigManager.Load` 用对应的代码默认值覆盖该文件并继续启动。

手动「获取远端配置」不走上面的自动顺序。主界面先弹出确认框，说明将覆盖本地的 `app.xml`、`plc.xml`、`api.xml`、`users.xml`。选否时 `RemoteConfigSync.Apply(confirmed: false, …)` 直接返回，不下载、不写文件。选是之后才下载。远端包缺三份必需文件时，不写本地文件。写入时只覆盖包里实际包含的文件：包里没有 `users.xml` 时，本地的 `users.xml` 保留。写入成功后走和保存配置相同的热加载：停监控、重读 XML、重建 PLC 和 API 客户端、`ReloadAddresses`、按测试类型重建实时页。热加载前正在监控时，完成后再启动。

`DatabasePath` 为相对路径时，相对配置目录，不相对程序目录。

## 3. 三份工站文件

### app.xml

`AppConfig`。运行时会读取的字段：

| 字段 | 默认 | 作用 |
|---|---|---|
| `EquId` | `OP010` | 工站号。引导文件的 `StationId` 为空时，更新和手动拉配置用它 |
| `WorkStationName` | `上位机模板工站` | 窗口标题和顶栏 |
| `Line` | `LINE-01` | 顶栏产线 |
| `Station` | `普通工站` | `首站` / `普通工站` / `尾站`，显示在顶栏 |
| `Section` | `default` | 段名。示例落库时写入记录的 `TestType` |
| `PollIntervalMs` | 50 | 主循环间隔，最小按 10 ms 执行 |
| `HeartbeatTicks` | 10 | 多少次轮询翻转一次心跳 |
| `RequiredSteps` | 10、20、30 | 出站前 `ProcessTrace.Check` 使用。空列表表示不校验 |
| `TestType` | `默认` | 「实时数据」页的类型，见开发手册 |
| `SnLength` | 18 | 示例进站校验。0 表示不校验长度。配置页允许 0～64 |
| `DatabasePath` | `Data\host.db` | SQLite 路径 |
| `Simulate` | false | true 时使用 `FakePlcClient` |
| `SimulateStepSeconds` | 0 | 大于 0 时仿真 PLC 自动推进流程字 |
| `EnableLogin` | false | 是否弹出登录 |
| `Theme` | `夜间` | `夜间` 或 `日间` |
| `AutoUpdate` | false | 是否向服务查询目标版本 |
| `StartWithWindows` | false | 当前用户登录后是否启动 |

属性网格里还有 `PcNo`、`SnPrefix`、`SaveTextLog`、`SaveDbLog`、`SessionTimeoutMinutes`。它们会保存，主程序当前不读取。

### plc.xml

连接参数和地址表在同一个文件里。连接字段：

| 字段 | 默认 | 作用 |
|---|---|---|
| `Protocol` | `SiemensS7` | 工厂按这个名字创建客户端 |
| `Address` | `192.168.0.1` | IP |
| `Port` | 102 | 端口小于等于 0 时，工厂改用该协议的默认端口 |
| `CpuType` | `S1200` | 仅西门子。`S1200` / `S1500` / `S300` / `S400` / `S200Smart` |
| `Rack` / `Slot` | 0 / 0 | 西门子机架和插槽 |
| `StationNo` | 1 | Modbus 站号，或欧姆龙节点号 |
| `ConnectTimeoutMs` / `ReceiveTimeoutMs` | 2000 / 2000 | 连接和读写超时 |
| `ReconnectDelayMs` | 2000 | 引擎两次 `OpenAsync` 之间的最短间隔 |

地址表 `Addresses` 的每一行是 `AddrOption`：`Name`、`Rw`（`R` / `W` / `RW`）、`Address`、`Length`、`DataType`、`Remark`。备注只给现场看，程序不读。

地址表只提供可配置的 PLC 点位。`StationContext` 用键名索引，`GetAddress` 返回地址字符串，键缺失时记一条警告并返回 null。`StationState` 由引擎和步骤写入，供界面显示流程字、SN、托盘、审查码和件数。

引擎固定使用这四个键：

| 键 | 方向（模板默认） | 默认地址 | 类型 | 引擎用途 |
|---|---|---|---|---|
| `MES_心跳` | RW | `M100.0` | Bool | 翻转心跳。键缺失则不写心跳 |
| `PLC_指令` | R | `MW200` | Word，长度 2 | 读两个 Word，第一个是流程字。缺失时监控无法启动 |
| `PLC_预留bool` | R | `M110.0` | Bool，长度 16 | 读预留位。长度以地址行的 `Length` 为准，缺省 16。键缺失则不读 |
| `MES_审查结果` | RW | `MW210` | Word | 回写审查码。键缺失则只更新内存状态 |

模板和 `ConfigManager.CreateDefaultPlc` 里还有三行，给步骤用，引擎轮询不读它们：

| 键 | 方向 | 默认地址 | 类型 |
|---|---|---|---|
| `MES_SN` | W | `DB1.DBB0` | String，长度 20 |
| `PLC_SN` | R | `DB1.DBB100` | String，长度 20 |
| `PLC_托盘号` | R | `MW220` | Word |

键名重复时索引保留第一行，并在加载时给出警告。

### api.xml

`ApiConfig`：`BaseUrl`、`TimeoutMs`（最小按 500 ms 使用）、`RetryCount`、`RetryBackoffSeconds`、`Enabled`、`Headers`、`Endpoints`。

模板端点：

| 键 | 路径 | 方法列 |
|---|---|---|
| `ApplySn` | `/api/ProcessStation/RequestSnNumber` | POST |
| `PassStation` | `/api/ProcessStation/PassStation` | POST |
| `UploadTestData` | `/api/TestData/UpLoad` | POST |
| `RegisterNg` | `/api/BadProduct/Register` | POST |

模板请求头是 `appId=template`、`appKey=change-me`。

`HttpApiClient.PostAsync` 按键名取相对路径，拼到基地址上，正文为 JSON，固定发送 POST。端点上的 `Method` 会保存，这个客户端不按它切换动词。`RetryCount` 是尝试次数，小于 1 时按 1 次。4xx 不重试；5xx 和异常按 `RetryBackoffSeconds * 当前次数` 秒退避。键名不存在时返回失败，消息为「api.xml 未配置端点」。

`Enabled` 为 false 时，`PostAsync` 返回成功且正文为 `{"Success":true,"Mesg":"接口已关闭"}`，`PingAsync` 返回 false，主界面 MES 灯为红色。

## 4. 配置页

主界面「系统配置」，或 `--config` 启动，打开 `ConfigForm`。四页：基础参数、PLC 连接、PLC 地址表、MES 接口。

打开时 `XmlConfigStore.Clone` 深拷贝三份配置。点取消则磁盘上的文件不动。点「保存并生效」后写回三份 XML。主窗口若在运行，会先停监控，再重建客户端并恢复。

保存前校验，出错则跳到对应页。主要规则：

- 轮询周期 10～5000 ms，心跳翻转至少 1，条码长度 0～64，数据库路径非空。
- IP 非空，端口 1～65535，协议必须在 `PlcDeviceCatalog` 的协议名里。
- 西门子 CPU 只能是 `S1200` / `S1500` / `S300` / `S400` / `S200Smart`。
- 机架 0～7，插槽 0～31，站号 1～247。这一条对所有协议生效，所以配置页不能把欧姆龙节点保存成 0。手改 XML 写成 0 时，欧姆龙客户端会改用 IP 最后一段，见 [设备](设备.md)。
- 超时大于 0。地址表不能空，键名不能空、不能重复，地址不能空，读写只能是 `R` / `W` / `RW`，并且必须有 `PLC_指令`。
- 接口启用时，基地址必须是 http 或 https，超时大于 0，重试次数不能为负，端点键不能重复，有键名的行必须有路径。

不阻止保存、但会另外提示的情况：地址表缺少 `AddressKeys` 里的其他键、开启了仿真、打开了登录。保存时会按「开机自启」同步注册表。

PLC 连接页的下拉、显隐、默认端口和说明都来自 `PlcDeviceCatalog.All`。可选型号：

| 显示名 | 协议 | 默认端口 | 显示的连接项 |
|---|---|---|---|
| 西门子 S7-1200 / 1500 | `SiemensS7` | 102 | IP、端口、机架、插槽。机架 0，插槽 0 |
| 西门子 S7-300 / 400 | `SiemensS7` | 102 | IP、端口、机架、插槽。机架 0，插槽 2 |
| 西门子 S7-200 Smart | `SiemensS7` | 102 | IP、端口。地址用 V 区 |
| Modbus TCP（通用） | `ModbusTcp` | 502 | IP、端口、站号，默认站号 1 |
| 汇川 Inovance（AM/H5U） | `InovanceTcp` | 502 | IP、端口、站号 |
| 台达 Delta（DVP/AS） | `DeltaTcp` | 502 | IP、端口、站号 |
| 三菱 MC（Q/FX5U/iQ-R） | `MelsecMc` | 6000 | IP、端口 |
| 欧姆龙 FINS（NJ/NX/CJ） | `OmronFins` | 9600 | IP、端口、节点号。清单里的默认节点是 0；配置页保存要求 1～247 |

选中型号后填入该型号的默认端口、机架、插槽和站号，并显示地址写法。

「连接测试」用当前页面上的值新建客户端，不使用上次保存的值。`OpenAsync` 成功后，地址表里有 `PLC_指令` 就再 `ReadWordAsync` 一次。连接失败时对 `HslDeviceBase` 调用同步的 `Ping()`：能 Ping 通提示检查端口、站号或机架槽号，不能 Ping 通提示检查网线、网段和电源。测试结束后立刻释放客户端。

「打开配置目录」用资源管理器打开 `ConfigDirectory`。「恢复默认值」会先确认「将四页配置全部恢复为出厂默认值」。确认后，编辑中的副本换成 `CreateDefaultApp` / `CreateDefaultPlc` / `CreateDefaultApi`，要点「保存并生效」才写盘。
