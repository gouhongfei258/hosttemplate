# HostTemplate

工站上位机。连 PLC，按流程字做进站、测试、出站，在主界面看当前状态，并在本机修改配置。程序更新走本线的后端服务，不走共享文件夹。

## 能做什么

- 监控台显示工站状态、流程字、条码、托盘、轨迹、良品和不良计数，以及程序报警。
- 「实时数据」页显示当前这一件的结果。模板自带一页示例，现场可以整页换成自己的画面。
- 「系统配置」可改工站参数、PLC 连接和地址、上位接口。保存后马上生效，不用重启。
- 工站配置和日志放在工控机自己的目录里（默认 `%ProgramData%\HostTemplate\config` 和 `Logs`），不跟程序版本走。本机没有配置时，先向本线服务要；服务也没有，再用程序里的模板。离线也能打开。
- 「获取远端配置」会先问是否覆盖本机文件。取消则一个字节都不改。
- 「程序更新」列出服务上的全部版本，可以装新版本，也可以回退。只有工站空闲时才会替换程序并重启：流程字是等待进站，没有产品在测，也没有步骤正在执行。
- 系统配置里可以打开「自动更新」。只在目标版本比当前新时后台下载，仍然等空闲才安装。
- 登录默认关闭。打开后按操作员、工程师、管理员区分权限。
- 顶栏可以在日间和夜间之间切换，选择会记住。

## 下载

发布包在 GitHub Releases：

https://github.com/gouhongfei258/hosttemplate/releases

每个版本有这些附件：

| 文件 | 用途 |
|---|---|
| `HostTemplate-<版本>.zip` | 解压后直接运行的程序目录 |
| `HostTemplate-<版本>-full.nupkg` | 给本线后端的 Velopack 全量包 |
| `releases.win.json` | 和 nupkg 一起交给后端的版本索引 |

在工控机上使用 zip：解压到固定目录，运行里面的 `HostTemplate.exe`。nupkg 不要当成普通压缩包解到程序目录。

## 第一次运行

1. 双击 `HostTemplate.exe`。
2. 程序旁边如果还没有 `bootstrap.xml`，会按 `%ProgramData%\HostTemplate` 生成一份。工站配置和日志都在这个目录里，以后换版本不会把它们清掉。
3. 要连本线服务时，用文本编辑器改程序旁边的 `bootstrap.xml`：
   - `ServiceBaseUrl`：例如 `http://10.0.0.8:5080`。留空则完全离线。
   - `StationId`：向服务要配置和版本时用的工站编号。留空则用配置里的工站号。
   - `ServiceToken`：服务开了令牌才填。
4. 本机还没有 `app.xml`、`plc.xml`、`api.xml` 时，程序会向服务要。服务没有，就用自带模板生成。

## 现场操作

| 做什么 | 怎么做 |
|---|---|
| 开始或停止监控 | 底栏「开始监控」「停止监控」。开始后按 PLC 流程字推进 |
| 把流程字拉回等待进站 | 「复位流程」 |
| 看报警 | 身份条下面的报警条。没有程序报警时显示「无程序报警」 |
| 切换日间或夜间 | 顶栏按钮。夜间界面下按钮写「日间」，反过来写「夜间」 |
| 改配置 | 「系统配置」。PLC 页可以先「连接测试」，再「保存并生效」 |
| 打开配置所在的文件夹 | 配置页里的「打开配置目录」 |
| 用服务上的配置覆盖本机 | 「获取远端配置」。确认后才覆盖，取消则本机文件不动 |
| 更新或回退程序 | 「程序更新」，选一个版本后点「安装此版本」。不空闲时会等空闲再装 |
| 自动更新 | 系统配置里打开「自动更新」 |
| 账号 | 默认不用登录。「账号管理」可以提前建账号。启用登录后，首次账号是 `admin` / `admin123`，会要求改密 |

窗口标题和右下角是当前程序版本。

只是把 zip 解压来运行、没有用 Velopack 安装时，「程序更新」会说明现在不能替换文件。

配置目录、加载顺序和更新规则的说明在 [配置与更新](docs/config-and-updates.md)。架构、加一个工站步骤、打包和后端怎么跑，写在 [开发手册](docs/开发手册.md)。
